## Decisions and guarantees

- R4 needs no replacement production guard on this baseline: integrated R2 already
  checks cancellation after interpreter/sandbox awaits and after spawn-spec construction,
  immediately before foreground/background launch. Deferred tests independently validate
  permission, resolve, wrap and spec boundaries, including completion of pending setup
  after the scheduler has returned cancelled. Plan/approval tightening still denies launch.
- R3 emits explicit success/failure, category, retry and effect facts at the shell source.
  Nonzero or null natural exit can follow partial effects, so the shared executor records
  failed + unknown effects. The actual dispatcher emits unknown, scheduler halts,
  uncertainty is recorded and no success is cached. Prelaunch rejection/setup/spawn
  failure is not_applied; cancellation before launch is distinct from a started timeout.
- stdout remains the last shell JSON field; stdout/stderr and exit facts survive shared
  normalization. Old tools without explicit timeout metadata retain the timeout defaults.
- Started background jobs retain the existing independent stop/deadline/quit lifecycle.
  No signal is attached to kill already-started background jobs on turn cancellation.
