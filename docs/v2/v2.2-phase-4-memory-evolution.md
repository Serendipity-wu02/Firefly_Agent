## 2. 衰减与过期机制 (Decay vs Expiration)

### 2.1 艾宾浩斯指数半衰期衰减模型 (Exponential Decay)
$$Strength(t) = Importance \times e^{-\frac{\ln 2 \cdot (t - t_{lastAccessed})}{halfLifeMs}} \times \left(1 + 0.2 \cdot \ln(1 + accessCount)\right)$$

1. **衰减行为**:
   - `L1_EPISODIC` 短时情景记忆按 7 天半衰期自然衰减；
   - 每次被召回使用（`accessCount` 递增）会提供对数强化，减缓衰减；
2. **完全免疫衰减**:
   - 标记为 `pinned: true` 或位于 `L2_SEMANTIC`（核心画像）的记忆条目**100% 免疫自然衰减**；
3. **只读性保障 (Read-Only Safety)**:
   - 检索时（`retrieve`）动态计算即时衰减强度并打分，**绝对不突变存储层**。

### 2.2 明确过期 (Expiration via TTL)
- `L0_WORKING` 瞬态记忆及带有明确 `expiresAt` 的记录在 $t \ge expiresAt$ 时立即标记为过期；
- 在维护周期（`runMaintenance`）中被原子化物理清理。

## 3. 冲突消解与历史保留 (Conflict Resolution & History Preservation)

当出现同作用域（`scope`）、同分层（`layer`）、同主键（`key`）但不同内容陈述时，`MemoryConflictResolver` 按严格确定的优先级阶梯仲裁：

```text
Priority 1: 用户显式来源 (source === "user_explicit" > "chat_extract")
Priority 2: 置信度高优先 (Confidence Difference >= 0.05)
Priority 3: 时间最新优先 (Recency / updatedAt)
Priority 4: 基础重要性优先 (Importance)
Priority 5: ID 字典序稳定保底 (Deterministic Tie-breaking)
```

### 3.1 历史可追溯性 (Full Audit History)
被取代的记录（`supersededRecords`）的内容、更新时间与取代原因被自动无损追加到胜出记录的 `metadata.history` 中：

```json
{
  "key": "代号",
  "value": "开拓者",
  "metadata": {
    "history": [
      { "value": "无名客", "updatedAt": 1000, "reason": "user_correction" },
      { "value": "银河球棒侠", "updatedAt": 2000, "reason": "user_correction" }
    ]
  }
}
```

### 3.2 偏好与关系冲突 (Preference & Relation Conflicts)
- `PreferenceItem` 冲突：同一 `subject` 极性或强度变更，最新时间戳覆盖；
- `RelationEdge` 冲突：同一 `(subject, predicate)` 关系边，高置信度与最新时间戳覆盖。

## 4. 记忆整合与层级升格 (Consolidation & Layer Evolution)

`MemoryConsolidator` 支持短时记忆向长期画像的平滑演进：

1. **频次强化升格 (Frequency-based Promotion)**:
   - `L1_EPISODIC` 记忆当 `accessCount >= 3` 时，自动升格为 `L2_SEMANTIC`；
   - 升格后清除 `expiresAt`（成为永久画像），并记录 `metadata.promotionReason = "access_frequency_reinforced"`。
2. **重要性直接升格 (High Importance Promotion)**:
   - `importance >= 0.85` 或显式置顶的 L1 记忆直接升格为 L2。
3. **多条关联记忆聚合 (Multi-record Consolidation)**:
   - 将零散的多条小记忆（如多次提到“常听爵士乐”、“喜欢萨克斯”）合并为包含全量实体与聚合历史的核心画像。

---

## 5. 维护协调与并发安全 (MemoryMaintenanceService)

- **批处理维护**: 通过 `maintenanceService.runMaintenance(now)` 按需或定时触发；
- **幂等性 (Idempotency)**: 连续多次执行维护流水线产生完全一致的稳定终态；
- **并发安全 (Concurrency Safety)**: 读写与维护操作均面向底层原子化存储接口，互不污染。
