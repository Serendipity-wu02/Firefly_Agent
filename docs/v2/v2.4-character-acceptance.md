## 1. 11 项架构模块逐项终审证据

### 1.1 Persona Acceptance — 【PASS】
- **单一真理源 (SSoT)**: 唯一 Canonical Persona 文件冻结于 `resources/persona/firefly.yaml`，严格由 `PersonaLoader` 单向只读解析；
- **零设定硬编码**: 业务逻辑与 fallback prose 彻底清空，完全杜绝在代码中硬编码人设口吻；
- **防篡改与不可变性**: `PersonaLoader.getProfile()` 返回深度冻结对象，外部对抗性输入无法篡改。

### 1.2 Knowledge Acceptance — 【PASS】
- **物理资源解耦**: 806 个世界观与设定资源物理分类存放于 `resources/world/`, `resources/story/`, `resources/knowledge/`, `resources/linguistics/`, `resources/character/`；
- **主观角色视角**: `CharacterKnowledgePerspective` 将客观背景知识转化为流萤第一人称体验与珍惜当下的处世哲学；
- **零事实捏造**: 对未提及的历史细节保持严谨，不编造非官方经历。

### 1.3 Relationship Acceptance — 【PASS】
- **真实 SSoT 链路**: 权威人物关系数据来源于 `resources/knowledge/facts.yaml` 及 `resources/knowledge/curated_cards/`，由 `RelationshipLoader` 动态加载，由 `RelationshipRegistry` 提供单例查询接口；
- **关系网络保真**: 开拓者（核心羁绊、绝对信任、害羞）、星核猎手（同伴家人、互相守护）、列车组与匹诺康尼人物（客气克制、审视与尊重）；
- **外部角色非多情化**: 未知 NPC 返回 `null`，外部势力人物严格限制为客观世界观视角，禁止伪造共同经历。

### 1.4 Emotion Acceptance — 【PASS】
- **语义状态模型**: `SemanticInnerState` 定义 7 种语义情绪枚举（`neutral`, `happy`, `shy`, `thinking`, `surprised`, `concerned`, `determined`）；
- **确定性仲裁分类**: 严格区分【外部用户身体不适/负向情绪 (`concerned`/`caring`)】与【流萤自身失熵症身体病理 (`thinking`/`reflecting`)】；
- **数值解耦**: 语义情绪判定完全基于语义上下文与对话特征，0 依赖旧数值宠物属性。

### 1.5 Behavior Acceptance — 【PASS】
- **高维行为决策源**: `BehaviorRuntime` 依据优先级确定性仲裁 8 类行为（`comfort_user`, `restrained_response`, `share_memory`, `reflect_origin`, `focused_execution`, `explore_knowledge`, `warm_conversation`, `idle_presence`）；
- **唯一决策权威**: 行为层统一输出高维决策，作为 downstream Text, Voice, Live2D 表现的唯一起点。

### 1.6 Embodiment Acceptance — 【PASS】
- **多模态表现计划**: `EmbodimentPlan` 由 `CharacterPolicyEngine.createEmbodimentPlan()` 统一编译生成；
- **表现一致性闭环**: Text（纯净台词）、Voice（声学意图与语速调制）、Visual（Live2D 目标动作）归属于同一个行为；
- **全局唯一关联追踪**: `correlationId` (`emb-timestamp-type-counter`) 贯穿计划生成、ChatMessage 实体、TTS 请求以及 Live2D IPC 调度。

### 1.7 Harness Presentation Acceptance — 【PASS / PENDING_MANUAL】

  - `DefaultAvatarResolver` 返回 `{ kind: "image", name: "流萤", src: ... }`；
  - Vite 打包生成产物 `dist/renderer/assets/firefly-mE4lp41h.png`；
  - `ChatMessageItem` 渲染真实图片头像，彻底清除 assistant 的“萤”字徽章及渐变假占位；
  - 自动 TTS 与手动点击 TTS 按钮均传递 `ChatMessage` 上的具身化元数据，参数与语速严格等价；
- **桌面真机视觉呈现 (PENDING_MANUAL)**: 无头测试环境中已验证 DOM/AST 与 Bundle 产物，真机桌面窗口视觉走查待人工最终确认。

### 1.8 Voice Acceptance (能力边界真实校准) — 【PASS】
- **实际消费能力 (PASS)**: `FireflyTtsDispatcher` 提取 `prosodyHint.pace` 调制实际语速（`slow` $\rightarrow$ `baseSpeed * 0.9` / `brisk` $\rightarrow$ `baseSpeed * 1.1`），下发至 GPT-SoVITS (`speed_factor`)、Custom Cloud 与 MiniMax；
- **元数据边界说明**: `pitch`、`volumeModifier`、`pauseLengthMs` 作为契约元数据存在于 `VoiceProsodyHint` / `EmbodimentPlan` 中，但**明确声明当前本地/云端推理引擎未消费此类声学微调参数，不作为已生效音频能力主张**；
- **Cache 隔离与台词纯净 (PASS)**: TTS Cache Key 仅纳入实际生效参数（`text`, `speed`, `pace`, `behaviorType`, `engineConfig`）；`speechText` 保持 100% 纯口语台词，无控制符污染。

### 1.9 Live2D Acceptance — 【PASS】
- **零新增资源 (assets = 0 diff)**: 100% 复用现有 11 个 Expression 与 6 个 Motion；
- **真实动作调度**:
  - 用户不适 (`comfort_user`) $\rightarrow$ `actionId: "touched"` (`expression4` 欣慰触动)；
  - 用户赞美 (`restrained_response`) $\rightarrow$ `actionId: "shy"` (`expression10` 害羞脸红)；
  - 回忆分享 (`share_memory`) $\rightarrow$ `actionId: "happy"` (`expression4` 欢喜)；
  - 自身病理 (`reflect_origin`) $\rightarrow$ `actionId: "sick"` (`expression7` 弱气沉思)；
  - 专注任务 (`focused_execution`) $\rightarrow$ `actionId: "reading"` (`Idle/1` 专注阅读待机)；
- **IPC 载荷**: `IPC.LIVE2D_PLAY_ACTION` 载荷携带 `correlationId` 与 `behaviorType`。

### 1.10 Memory Boundary Acceptance — 【PASS】
- **只读个性化影响**: 长期记忆（如用户饮食偏好、天台约定）可作为上下文影响话题选择；
- **边界坚固性**: Memory 严格禁止修改底层 Persona、官方 Relationship 事实或 Canonical Knowledge。

### 1.11 Legacy Numeric State Isolation — 【PASS】
- **旧数值宠物状态隔离**: `affection`, `hunger`, `energy`, `health`, `attention`, `decay`, `feeding`, `treatment` 完全退出角色人格与行为决策；
- **极值不变性测试**: 传入极限低数值（energy 0, health sick）与极限高数值（energy 100, health healthy），角色的行为决策、语义情绪与具身化计划 100% 完全一致。
