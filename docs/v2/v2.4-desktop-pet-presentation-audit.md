## 4. SpeakingMotionController 视觉覆盖问题修复

- **原问题**: `setSpeaking(true)` 强行执行 `manager.playActionId("talking")`，`setSpeaking(false)` 强行执行 `manager.playActionId("idle")`，导致 Behavior 赋予的生动表情（如羞涩 `shy`、欣慰 `happy`、感动 `touched`、沉思 `thinking`）在语音播放起止瞬间被覆盖清除。
- **修复方案**:
  - `SpeakingMotionController` 职责严格限制在口型同步控制；
  - `setSpeaking(true)` 仅调用 `this.mouthSync.start(durationMs)`；
  - `setSpeaking(false)` 仅调用 `this.mouthSync.stop()`；
  - **彻底移除一切表情与动作的自行切换逻辑**。

---

## 5. ExpressionResetController 视觉覆盖问题修复

- **原问题**: 任意表情被触发后，`ExpressionResetController` 固定在 5000ms 后调用 `manager.setExpression("")`，造成表情在 5 秒后被无条件重置为白板。
- **修复方案**:
  - `ExpressionResetController` 重置目标固定为官方默认表情 `expression00`；
  - 默认关闭无条件 5 秒定时器，仅在动作目标显式携带 `temporary: true` 时才启动定时重置；
  - 角色表情状态生命周期完全由 `BehaviorDecision` / `EmbodimentPlan` 决定。

## 8. 窗口尺寸与可见角色剪影边界度量 (Measurement Only)

通过 WebGL FrameBuffer `gl.readPixels` 全像素 Alpha 深度扫描现场实测数据如下：

### 8.1 基础几何容器与窗口尺寸
- **BrowserWindow 实际尺寸**: `238 × 308` (基准 `340 × 440` × `petScale: 0.7`)
- **Canvas 实际尺寸**: `238 × 308` (devicePixelRatio = 1)
- **Live2D Model 原始画布尺寸 (`internalModel`)**: `4464 × 3285` (宽高比 1.3588，横向宽幅设计)
- **Live2D Model 渲染几何边界 (`model.width` / `model.height`)**: `214 × 158` (Pixi Container Bounds)
- **模型缩放率 (`model.scale.x` / `model.scale.y`)**: `0.0480` (`fitScale = min(scaleX, scaleY) = (238 * 0.9) / 4464`)
- **模型定位 (`model.x` / `model.y`)**: `x = 119, y = 308` (锚点 `anchor = (0.5, 1.0)` 底部居中)

### 8.2 角色肉眼可见实际剪影边界 (`Visible Character Silhouette Bounds`, `alpha > 15`)
- **采样有效像素点数 (`Hit Pixel Count`)**: **14,059 个不透明像素**
- **可见角色实际像素范围**:
  - `minX = 20px`, `maxX = 217px`
  - `minY = 167px`, `maxY = 296px`
- **可见角色肉眼实际宽度 (`Visible Character Width`)**: **`198 px`**
- **可见角色肉眼实际高度 (`Visible Character Height`)**: **`130 px`**
- **透明留白区域 (`Transparent Padding`)**:
  - **上方留白 (`Padding Top`)**: **`167 px`** (占窗口总高度 54.2% 的空白区域)
  - **下方留白 (`Padding Bottom`)**: **`11 px`**
  - **左侧留白 (`Padding Left`)**: **`20 px`**
  - **右侧留白 (`Padding Right`)**: **`20 px`**
- **可见角色在窗口中的实际占比**:
  - 视觉高度占比: `130 / 308 = 42.21%`
  - 视觉宽度占比: `198 / 238 = 83.19%`

> **测量结论与原因分析**：
> 1. 当前并非窗口整体太小（窗口高度已有 308px），而是 Live2D 模型原始画布宽度极大（4464px 横向宽幅包含武器/特效等透明扩展），受限于宽度自适应约束（`scaleX = 0.048`），导致整个模型被等比缩放到了 158px 高度；
> 2. 在 158px 模型高度中，流萤角色的可见像素集中在下半区（`167px ~ 296px`），上方产生了高达 **167px** 的巨大透明留白；
> 3. 因此用户肉眼看到的流萤实际高度仅有 **130px**（与目标视觉高度 220px～300px 存在明显差距）。
> *(本轮严格遵守约束，仅输出测量数据，未自行选择或拍板最终尺寸调整方案)*

## 9. Target Visible Character Size Calculation (目标可见角色尺寸重新推导)

根据实测的肉眼可见剪影数据（`Visible Character = 198 × 130 px`，剪影宽高比 `1.523`，原始画板 `4464 × 3285 px`），针对产品目标范围 **`220px ~ 300px`** 建立 5 档严谨推导模型：

### 9.1 概念边界严格隔离
- **Window Bounds (BrowserWindow)**: 操作系统 Electron 透明窗口矩形边界；
- **Model Bounds (Pixi Container)**: Live2D 原始宽幅画板（`4464 × 3285`）缩放后的几何容器；
- **Visible Character Bounds (Silhouette)**: 用户肉眼真正看到的流萤不透明像素边界（`alpha > 15`）。
> **核心原则**：产品约束（220px～300px）所指为 **Visible Character Bounds**，绝非 Window 框尺寸。

## 10. Desktop Pet 唯一 Visual Decision Path

```text
BehaviorRuntime (决定高维行为倾向)
      ↓
EmbodimentAdapter (编译出唯一 EmbodimentPlan: Text, Voice, Visual)
      ↓
WindowManager.sendToPet(IPC.LIVE2D_PLAY_ACTION, visual.target)
      ↓
Live2DManager.playTarget(target)
      ↓
Canvas WebGL Render
```

- **Voice**: 仅负责音频回放与实时口型同步 (`ParamMouthOpenY`)；
- **Legacy State**: 仅保留状态持久化与兼容接口支持；
- **Live2D**: 唯一受控于 `EmbodimentPlan`；
- **默认形态**: 严格固定为 `expression00` + `Idle/0`（禁止 `Idle/1`, `Idle/2`, 随机表情或旧状态动作成为默认常驻）。
