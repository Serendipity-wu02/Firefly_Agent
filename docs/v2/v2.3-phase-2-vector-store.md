## 1. 架构总览与分层数据流 (Architecture Flow)

Phase 2 建立了独立的知识库向量化基础设施。`EmbeddingService` 与 `VectorStore` 仅消费 Phase 1 产出的 `KnowledgeChunk`，不直接读取原始 `resources/`，且与 `MemoryStore` 绝对隔离。

```text
       KnowledgeChunk[] (5665 Chunks from Phase 1)
                           │
                           ▼
                  VectorIndexService
                           │
             ┌─────────────┴─────────────┐
             │                           │
      [Unindexed Chunks]          [Indexed & Unchanged]
             │                           │
             ▼                           ▼
     IEmbeddingProvider           Skipped (220ms)
  (Deterministic / ONNX / API)
             │
             ▼
     VectorRecord[] (384-dim)
             │
             ▼
        IVectorStore
  (FileVectorStore / InMemory)
             │
             ▼
  data/knowledge/vector_index.json
```

## 2. 核心抽象与接口规范 (Core Interfaces)

### 2.1 嵌入提供商接口 (IEmbeddingProvider)
```typescript
export interface EmbeddingModelInfo {
  model: string;                      // 例如 "deterministic-bge-384"
  dimension: number;                  // 例如 384
  version?: string;                   // 例如 "1.0.0"
}

export interface IEmbeddingProvider {
  readonly modelInfo: Readonly<EmbeddingModelInfo>;
  embedText(text: string): Promise<number[]>;
  embedBatch(texts: string[]): Promise<number[][]>;
}
```

### 2.2 向量存储接口 (IVectorStore)
```typescript
export interface VectorRecord {
  chunkId: string;                    // 关联 KnowledgeChunk ID (唯一键)
  documentId: string;                 // 所属文档 ID
  sourceUri: string;                  // 原始来源路径 (如 "knowledge/facts.yaml")
  embedding: number[];                // 浮点向量 (384 维归一化)
  text: string;                       // 切片原文 (只读溯源)
  canonicalPriority: number;          // 权威优先级 (0.50 ~ 1.00)
  chunkType?: string;                 // 切片类型
  modelInfo: EmbeddingModelInfo;      // 模型名称与维度元数据
  createdAt: number;
  updatedAt: number;
}

export interface IVectorStore {
  upsert(records: VectorRecord[]): Promise<void>;
  delete(chunkIds: string[]): Promise<number>;
  deleteBySource(sourceUri: string): Promise<number>;
  get(chunkId: string): Promise<VectorRecord | null>;
  query(queryVector: number[], topK?: number, filter?: VectorFilter): Promise<VectorQueryResult[]>;
  count(): Promise<number>;
  list(): Promise<VectorRecord[]>;
  clear(): Promise<void>;
  flush(): Promise<boolean>;
  reload(): Promise<void>;
}
```

## 3. 存储实现与高可用机制 (Storage & Recovery)

### 3.1 原子文件持久化 (Atomic Persistence)
- `FileVectorStore` 使用写入临时文件 `${filePath}.tmp` 后原子 `rename` 的策略，彻底防止断电或进程崩溃造成的 JSON 文件损坏；
- 遵循 `version: 1` 模式版本校验。

### 3.2 损坏自愈与备份 (Corruption Recovery)
- 当遇到非法或被破坏的 JSON 文件时，自动将其复制为 `${filePath}.corrupt-${timestamp}.bak` 进行持久保留，并以安全空集合初始化重载，保障应用永不崩溃。

### 3.3 增量索引与 Manifest 同步 (Incremental Indexing)
- `VectorIndexService` 在执行 `indexChunks()` 时自动检查现有向量记录；
- 若 `chunkId`、`model`、`dimension` 完全一致，自动跳过嵌入运算；
- `syncWithManifest()` 自动剔除已删除文件的废弃切片向量。
