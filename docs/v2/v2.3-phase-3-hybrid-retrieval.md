## 1. 架构总览与双路召回数据流 (Dual-Stream Architecture)

```text
                           User / Agent Query
                                   │
                 ┌─────────────────┴─────────────────┐
                 │                                   │
                 ▼                                   ▼
        [Lexical Stream]                     [Vector Stream]
        LexicalRetriever                     VectorRetriever
        (BM25 / Token / Entity / Heading)   (IEmbeddingProvider + IVectorStore)
                 │                                   │
                 ▼                                   ▼
        LexicalCandidates (50)              VectorCandidates (50)
                 │                                   │
                 └─────────────────┬─────────────────┘
                                   │
                                   ▼
                       Candidate Deduplication
                                   │
                                   ▼
                           KnowledgeReranker
        ┌─────────────────────────────────────────────────────────┐
        │  Score = w_ent*S_ent + w_lex*S_lex + w_vec*S_vec        │
        │          + w_canon*S_canon + w_time*S_time              │
        │                                                         │
        │  Adversarial Relevance Gating (零相关高权威降为 0)       │
        │  Deterministic Tie-Breaker (Score -> Priority -> ID)     │
        └─────────────────────────────────────────────────────────┘
                                   │
                                   ▼
                       Top-K ScoredKnowledgeChunks
```

## 2. 核心模块与权重策略 (Module Design & Policy)

### 2.1 词法检索器 (LexicalRetriever)
- 基于关键词分词、精准短语包含、Markdown 标题路径（`headingPath`）、显式标签（`keywords`）与预标注实体（`entityNames`）综合打分；
- 具备高效内存过滤（支持按 `minPriority`、`sourceTypes` 筛选）。

### 2.2 向量密集检索器 (VectorRetriever)
- 面向 `IEmbeddingProvider` 与 `IVectorStore` 抽象；
- 将高维密集余弦相似度（`0.0 ~ 1.0`）映射为向量候选分数，并自动还原完整的 `KnowledgeChunk` 元数据。

### 2.3 5 维加权重排序器 (KnowledgeReranker)
默认策略配置：
```typescript
export const DEFAULT_HYBRID_RETRIEVAL_POLICY: HybridRetrievalPolicyConfig = {
  weights: {
    entity: 0.35,     // 实体精准匹配权重 (最高权重，确保问特定人物/设定时精准命中)
    lexical: 0.25,    // 倒排词频与关键词命中权重
    vector: 0.20,     // 向量语义相似度权重
    canonical: 0.10,  // 权威优先级权重 (firefly.yaml/facts.yaml 优先)
    timeline: 0.10,   // 剧情时间线匹配权重 (penacony / glamoth / stellaron_hunter)
  },
  candidatePoolSize: 50,
  minFinalScore: 0.05,
  defaultTopK: 5,
};
```

### 2.4 对抗性安全门控 (Adversarial Relevance Gating)
- **问题**: 若仅依赖权威优先级（`canonicalPriority = 1.0`），一个关于“阿兰”的查询可能会被高权威但完全不相关的“流萤人设”占满 Top-K；
- **防护**: `KnowledgeReranker` 引入内容相关性门控（`contentRelevance = 0.5*lexical + 0.3*vector + 0.2*entity`），若相关性低于 `0.05`，最终得分强制置 `0`，杜绝不相关的高优先级语料污染。

### 2.5 确定性决胜排序 (Deterministic Tie-Breaking)
排序严格按照以下 4 级决胜规则，保障任何候选顺序排列下输出 100% 确定可复现：
1. `finalScore` 降序
2. `chunk.canonicalPriority` 降序
3. `breakdown.vectorScore` 降序
4. `chunk.id` 字典升序

## 3. 生产就绪度说明 (Production Readiness Gap)

> [!IMPORTANT]
> **真实语义模型说明 (Production Embedding Statement)**:
> 1. 当前代码中使用的 `DeterministicEmbeddingProvider` 是**基于字符 n-gram 哈希投射的基础设施与测试 Provider**，不具备 Transformer 深度语义泛化能力；
> 2. 架构已通过 `IEmbeddingProvider` 抽象完成彻底解耦。生产部署时只需传入 `LocalEmbeddingProvider` (ONNX Runtime / Transformers.js) 或云端 API Provider，即可平滑升级为工业级语义 RAG，**上层检索器与 Agent Core 零修改**。
