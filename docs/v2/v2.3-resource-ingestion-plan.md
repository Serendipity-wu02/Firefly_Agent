## 2. 差异化切片策略设计 (Differentiated Chunking Strategy)

为避免简单按固定字符数粗暴切断带来的语义撕裂，摄取引擎制定 7 类专属分块规则：

### 2.1 规则 1：`facts.yaml` 零损耗原子切分 (Atomic Fact Chunking)
- **输入**: `knowledge/facts.yaml`
- **规则**: 解析每个 YAML 条目，将 `entity`、`scene`、`source`、`fact`、`keywords` 构造成单个独立 Chunk；
- **元数据保留**:
  - `chunkType = "atomic_fact"`
  - `entityNames = [item.entity]`
  - `keywords = item.keywords.split(' ')`
  - `canonicalPriority = 0.95`
- **优势**: 100% 保持事实完整性，命中时直接提取完整断言，无截断噪点。

### 2.2 规则 2：`knowledge/*.md` 标题语义小节切分 (Heading Section Chunking)
- **输入**: `firefly_lore.md`, `amphoreus_lore.md`, `two_phase_paradise_lore.md` 等 6 篇
- **规则**: 以 `## ` 二级标题为切分边界；若单个小节超过 1200 字符，按 `### ` 三级标题进一步细分；
- **元数据保留**:
  - `headingPath = [主标题, 小节标题]`
  - `perspective = "first_person"`
  - `canonicalPriority = 0.85 (firefly_lore) / 0.75 (world_lore)`

### 2.3 规则 3：`knowledge/curated_cards/*.md` 整卡原子摄取 (Card Chunking)
- **输入**: 29 篇精选事件与人物卡片（如 `初次相遇.md`, `白厄.md`）
- **规则**: 每个 `.md` 文件整体作为一个独立的 `curated_card` Chunk（平均 300~800 字符）；
- **元数据保留**:
  - `chunkType = "curated_card"`
  - `cardTitle = 文件名.replace('.md', '')`
  - `canonicalPriority = 0.85`

### 2.4 规则 4：`流萤/主线剧情文本/*.md` 对话场景分块 (Scene Dialogue Chunking)
- **输入**: 22 篇匹诺康尼主线剧本文档
- **规则**: 识别对话中的发言人标记（如 `流萤:` / `开拓者:` / `黄泉:`）与场景切换线，以场景或对白轮次聚合（约 600~1000 tokens），保留相邻场景 100 tokens 重叠。

### 2.5 规则 5：`wiki/角色/*.txt` 角色档案结构化切分
- **输入**: 98 篇角色百科
- **规则**: 依据文本内的 section header（如 `【角色故事 1】`, `【角色语音】`, `【技能描述】`）拆分为独立子 Chunk，便于精准命中“某角色的技能”或“某角色的背景故事”。

### 2.6 规则 6：`wiki/开拓任务/*.txt` 长文剧情滑动窗口
- **输入**: 438 篇全剧情文本
- **规则**: 采用 800 tokens 窗口大小 + 100 tokens 重叠步长滑动切分，保留前后文语境。

## 4. 重复检测与多源冲突消歧策略 (Deduplication & Conflict Resolution)

### 4.1 重复现象分析 (Duplicate Analysis)
全量 806 个文件中存在合理的多层次内容重叠：
- **第一人称传记 vs 剧本实录**: `firefly_lore.md`（“我主动让死亡贯穿自己”）与 `流萤/主线剧情文本/7. 是谁杀死了.md`（完整旁白与台词实录）；
- **精选卡片 vs Wiki 任务**: `curated_cards/初次相遇.md` 与 `wiki/开拓任务/黄金年代的故事.txt`；
- **自机角色档案 vs 任务对话**: `wiki/角色/流萤.txt` 与 `流萤/角色游戏文本/角色故事1.md`。

### 4.2 消歧与覆盖规则 (Shadowing Rules)
1. **不物理删除任何原始文件**: 保持原始 resources 完整性；
2. **权威优先级遮蔽 (Canonical Priority Shadowing)**:
   - 当用户提问流萤自身感受与第一人称事实时，P1/P2/P4 知识块赋予极高加权，自然优先召回；
   - 当用户提问通用世界设定或第三方角色细节时，P6/P7 Wiki 知识块填补知识盲区；
3. **Chunk 级指纹去重**: 在向量化前，若两个 Chunk 的实体集完全相同且 Jaccard 相似度 $> 0.90$，仅保留优先级更高源的 Chunk。
