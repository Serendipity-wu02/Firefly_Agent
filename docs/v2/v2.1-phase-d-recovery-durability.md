## 1. 核心架构与状态机 (Execution State Machine)

### 1.1 Run 状态机转换图
```text
           ┌──────────────────────┐
           │         idle         │
           └──────────┬───────────┘
                      │
                      ▼
           ┌──────────────────────┐
           │     initializing     │
           └──────────┬───────────┘
                      │
                      ▼
 ┌─────────────────► running ◄──────────────────┐
 │                    │   │                     │
 │          ┌─────────┘   └──────────┐          │
 │          ▼                        ▼          │
 │   ┌──────────────┐         ┌──────────────┐  │
 └───┤  compacting  │         │  recovering  ├──┘
     └──────────────┘         └──────────────┘
            │                        │
            ▼                        ▼
     ┌──────────────┐         ┌──────────────┐
     │  cancelling  │         │  timed_out   │

            │                        │
            ▼                        ▼
     ┌──────────────┐         ┌──────────────┐

     ┌──────────────┐         ┌──────────────┐
     │  completed   │         │    failed    │
```

### 1.2 三维状态解耦体系
- **RunState**：`idle` | `initializing` | `running` | `compacting` | `recovering` | `cancelling` | `cancelled` | `timed_out` | `completed` | `failed` | `resumable`
- **StepState**：`pending` | `running` | `waiting_tool` | `waiting_llm` | `completed` | `failed` | `cancelled`
- **ToolSideEffectState**：`not_started` | `started` | `completed` | `failed` | `unknown`

## 2. Checkpoint & Resume 系统设计

### 2.1 结构解耦与脱敏序列化
- **ICheckpointPolicy**：决定快照触发时机（默认触发点：`run_initialized`、`step_start`、`llm_completed`、`tool_round_completed`、`compaction_completed`、`recovery_started`、`run_completed`）。
- **ICheckpointStore**：
  - `InMemoryCheckpointStore`：内存字典映射，适合快速测试；
  - `FileCheckpointStore`：支持 `${id}.tmp` $\rightarrow$ `${id}.json` 原子文件重命名、Schema 版本校验与损坏文件隔离。
- **脱敏保障**：严格过滤 `AbortController`、`Promise`、`Audio`、`Electron` 句柄等不可序列化对象。

### 2.2 副作用安全与断点恢复协议 (Side Effect Safety & Resume)
- **恢复合法性校验**：`completed`（已完成）与 `cancelled`（用户主动取消）的 Run **严禁自动恢复**。
- **防止重复副作用**：若快照中存在 `sideEffectState === "started"` 或 `"unknown"` 但未记录结果的工具调用，恢复器将主动注入合成中断标记（`interrupted_prior_to_completion`），使大模型在下一轮获得明确上下文，绝不盲目重新触发具有破坏性的外部操作。

## 3. Provider 级故障自愈与恢复预算 (Recovery Manager)

```text
LLM Provider 请求
        │
        ▼
   发生异常/拒绝
        │
        ▼
[ErrorClassifier 错误分类]
 ├─ 400 Context Overflow ──► [触发 Emergency Compaction ──► 重新发起请求]
 ├─ 429 Rate Limit ────────► [指数退避延时 (delay = backoff * 2^attempt) ──► 重试]
 ├─ 5xx Server / Socket ───► [限制次数瞬态重试]
 └─ 401 / 403 / Fatal ─────► [标记 failed 终止运行，不无限死循环]
```
