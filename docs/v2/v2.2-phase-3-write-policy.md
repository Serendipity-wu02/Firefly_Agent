## 1. 架构总览与数据流向 (Architecture & Flow)

在 Firefly-Agent 中，**对话不等于记忆 (Conversation $\neq$ Memory)**。必须经过严格的策略过滤网，只有具备长期价值或明确语义的陈述才允许进入持久化记忆体系。

```text
    User / Tool / Agent Observation
                   │
                   ▼
       MemoryWriteService.write()
                   │
                   ▼
           MemoryWritePolicy
       (闲聊/瞬态/低价值过滤网)
        /                     \
       / [Rejected]            \ [Accepted]
      ▼                         ▼
Reject Decision        ImportanceEvaluator
(0 Store Mutation)     (内在留存价值打分 0.0~1.0)
                                │
                                ▼
                       Deduplication & Correction Check
                                │
                                ├──> [Duplicate] -> increment accessCount
                                ├──> [Correction] -> audit history update
                                └──> [New Record] -> store.saveRecord()
                                                      + Entity / Relation / Preference
```

## 2. 写入策略分类体系 (Write Policy & Memory Categories)

| 类别 (Category) | 语义定位 | 默认目标层级 | 默认作用域 | 典型示例 | 处理动作 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`profile`** | 用户基础画像（姓名、生日、身份、禁忌） | `L2_SEMANTIC` | `user` | “我叫开拓者”、“我对坚果过敏” | **准入** (Importance $\ge 0.95$) |
| **`preference`** | 明确喜好与习惯（音乐、饮食、话题） | `L2_SEMANTIC` | `user` | “我最喜欢吃橡木蛋糕卷” | **准入** (同步生成 `PreferenceItem`) |
| **`relation`** | 人际关系与情感纽带 | `L1_EPISODIC` / `L2` | `user` | “流萤是我特别信任的人” | **准入** (同步生成 `RelationEdge`) |
| **`event`** | 重要约定与里程碑事件 | `L1_EPISODIC` / `L2` | `user` | “约定周末在天台看流星雨” | **准入** (Importance $\ge 0.75$) |
| **`entity`** | 具名实体与客观概念 | `L1_EPISODIC` | `user` | “格拉默是帝国故土” | **准入** (同步生成 `EntityNode`) |
| **`working_state`** | 会话临时状态与短期上下文 | `L0_WORKING` | `session` | “今天有点累”、“正在写周报” | **准入** (带默认 1h TTL，到期即焚) |
| **`casual_chat`** | 日常问候与寒暄 | - | - | “你好”、“今天天气不错” | **直接拦截 (REJECT)** |
| **`ephemeral_chat`**| 纯表情与语气词 | - | - | “哈哈哈哈”、“嗯嗯” | **直接拦截 (REJECT)** |
| **`system_noise`** | 渲染或系统调试日志 | - | - | “render cycle 12” | **直接拦截 (REJECT)** |

## 3. 重要性评估模型 (ImportanceEvaluator)

重要性评分是衡量记忆**“本身有多值得被长久留存”**的内在属性，与检索时计算的“与 Query 相关度得分”完全解耦。

$$Score_{importance} = \text{clamp}_{[0.0, 1.0]}\left(BaseCategoryScore + S_{explicit} + S_{correction} + S_{pinned}\right)$$

1. **基础分类分值**:
   - `profile`: $0.95$
   - `preference`: $0.85$
   - `relation`: $0.80$
   - `event`: $0.75$
   - `entity`: $0.65$
   - `working_state`: $0.35$
   - `casual_chat` / `ephemeral_chat` / `system_noise`: $0.10$
2. **显式度增益**: `source === "user_explicit"` $+0.05$；
3. **纠错强化**: `isCorrection === true` $\Rightarrow$ 基础分至少 $0.90$；
4. **固化保障**: `pinned === true` $\Rightarrow$ 基础分至少 $0.95$。

## 4. 去重与显式纠错机制 (Deduplication & Correction)

1. **完全重复记忆 (Identical Duplicate)**:
   - 匹配同 `(scope, layer, key)` 且 `value` 相同；
   - 动作：不新增冗余记录，将已有记录的 `accessCount + 1`，刷新 `lastAccessedAt`。
2. **显式用户纠错 (User Correction)**:
   - 触发条件：`isCorrection === true` 或同主键提供新值；
   - 动作：
     1. 更新记录当前 `value`；
     2. 将旧值追加至 `metadata.history`（记录 `{ value: oldValue, updatedAt: now, reason: "user_correction" }`）；
     3. 刷新 `updatedAt` 与 `importance`；
     4. 为 Phase 4 完整冲突消解预留标准审计链。

---

## 5. 存储门面与架构解耦 (MemoryWriteService)

- **纯门面设计**: `MemoryWriteService` 作为写入入口，负责调度 Policy、ImportanceEvaluator 与 `IMemoryStore`；
- **核心隔离保证**:
  - `FireflyAgentCore` 与上下文插槽不感知写入评分与去重细节；
  - 拦截项（`accepted === false`）**零触碰存储层**；
  - 100% 独立于 Live2D、TTS 与 QQ Music。
