# Firefly-Agent V2.4: 行为决策层架构规范 (Behavior Decision Layer Architecture)

- **版本基线**: Firefly-Agent V2.4 (`firefly-v2.4-alpha1`)
- **执行时间**: 2026-09-01
- **核心定位**: **建立高维语义“行为决策层”（Behavior Decision Layer），作为角色外显表现的唯一真源决策层（SSoT），负责将内在状态（Semantic Emotion）、用户意图、同伴关系与长期记忆（Memory）仲裁为统一的确定性行为决策（BehaviorDecision），并同时生成 Text、Voice、Visual 三路不矛盾的多模态表达倾向（MultimodalExpressionIntent），为下一阶段的 Live2D / TTS Embodiment 准备纯净的消费契约。**

## 2. Behavior 是唯一决策源 (Single Source of Truth for Behavior)

在 V2.4 架构中，系统**不再分别决定文字怎么说、声音怎么发、动作怎么做**。
**所有的外显表现必须来自同一个 `BehaviorDecision`**：

```typescript
export interface MultimodalExpressionIntent {
  /** 文本表达倾向（指导 LLM 口语生成风格、句式与停顿） */
  readonly text: string;
  /** 声音表达倾向（指导 TTS 声学特征、语速、音调、气声与停顿） */
  readonly voice: string;
  /** 视觉表现倾向（指导 Live2D 姿态、眼神方向、呼吸节奏与张力） */
  readonly visual: string;
}
```

### 多模态一致性保证示例（以 `comfort_user` 为例）
- **Behavior**: `comfort_user` (关怀抚慰)
- **Text Intent**: 使用极度温柔的短句与轻声安慰，多用省略号「…」，体贴询问并表达静静陪伴。
- **Voice Intent**: 语速明显放慢，音调柔和下降，加入温暖气声与耐心停顿，语气低沉温润。
- **Visual Intent**: 眼神微垂关切，身体微微前倾保持倾听姿态，动作克制平缓，避免剧烈晃动。
- **结论**: 文字、声音、视觉由同一行为源统领，**杜绝三路表现自相矛盾**。

## 3. 核心行为语义类型 (BehaviorType)

行为决策层定义了 8 大高维行为语义类型，**不与任何具体 Live2D Action ID 或动画硬编码绑定**：

| 行为类型 (`BehaviorType`) | 默认优先级 | 触发语境 | 典型行为姿态与说明 |
| :--- | :---: | :--- | :--- |
| **`comfort_user`** | **100** | 用户表达疲惫、头疼、生病、失落或挫折 | 最高关怀优先。轻声、温柔、主动倾听并抚慰对方。 |
| **`focused_execution`** | **80** | 工作模式 (`work_mode`) 或用户下达明确任务协助指令 | 专注高效。保持专业护盾姿态，允许调用工具并汇报进度。 |
| **`restrained_response`** | **70 / 60** | 针对角色的夸奖、外貌赞美或亲密互动 | 克制羞涩。目光移开、轻声否认、善用省略号停顿。 |
| **`share_memory`** | **70 / 60** | 提及橡木蛋糕卷、看星星、烟花、亲历故事或长期约定 | 欣喜温和。分享共同经历的美好时光与生活向往。 |
| **`reflect_origin`** | **60** | 探讨失熵症、格拉默铁骑、火萤机甲与萨姆驾驶员身世 | 沉静思考。以第一人称回忆身世，流露对当下的珍视。 |
| **`explore_knowledge`** | **50** | 宏观世界观、星神、派系势力设定探讨 | 客观理清线索。审慎分析宇宙情报。 |
| **`warm_conversation`** | **50** | 日常闲暇交流、通用问候 | 自然陪伴。轻声柔和地互动交谈。 |
| **`idle_presence`** | **10** | 无交互输入、窗口静置 | 静默待机。不触发主动发声。 |

## 4. 行为决策契约 (BehaviorDecision Contract)

定义于 [`src/main/character/behavior-types.ts`](file:///e:/Google-Antigravity/working/Firefly-Pet/src/main/character/behavior-types.ts)：

```typescript
export interface BehaviorDecision {
  /** 决策生成的行为语义类型 */
  readonly type: BehaviorType;
  /** 行为决策的确定性数值优先级 */
  readonly priority: number;
  /** 行为决策的程序化可解释性原因 (Runtime reason only) */
  readonly reason: string;
  /** 是否需要主动发声/生成回复 */
  readonly shouldRespond: boolean;
  /** 是否需要进入外显表现层 (供下一阶段 Embodiment 消费) */
  readonly requiresEmbodiment: boolean;
  /** 是否允许工具动作调用 (如播放音乐、系统控制) */
  readonly allowToolExecution: boolean;
  /** 关联的完整语义内在状态 */
  readonly innerState: SemanticInnerState;
  /** 是否受到了用户长期记忆 (Memory) 的个性化影响 */
  readonly memoryInfluenced: boolean;
  /** 统一衍生的多模态表达倾向 (文本、声音、视觉) */
  readonly multimodalIntent: MultimodalExpressionIntent;
  /** 决策生成时间戳 */
  readonly timestamp: number;
}
```

## 5. Memory $\rightarrow$ Behavior 深度融合 (Read-Only)

在 V2.4 行为决策层中，长期记忆（Memory）正式参与行为仲裁：
1. **偏好与约定协同**：当记忆中包含用户喜好（如“喜欢甜点”、“偏好夜间看星星”）或历史约定（如“匹诺康尼重聚”），且当前对话命中相关线索时，系统自动标记 `memoryInfluenced = true`，并将行为决策优先级从普通闲聊（50）提升至关系互动层级（70），决策原因显式注明依据；
2. **只读安全性保证**：行为决策层**只读检索** Memory 上下文，**绝对不向 `MemoryStore` 自动写入任何记忆记录**；
3. **不可变性边界**：长期记忆只影响个性化交互态度，**绝对不能改写流萤的 Persona、核心价值观或官方同伴关系事实**。

## 6. 严格区分“外部用户不适”与“流萤自身病理/身世”

| 行为维度 | 外部用户不适 (User Distress) | 流萤自身病理/身世 (Self Physical / Entropy Loss) |
| :--- | :--- | :--- |
| **触发特征** | “我头疼/我累了/我生病/我好难过/救救我” | “失熵症/身体解离/医疗舱/格拉默铁骑/AR-26710” 或 `selfPhysicalContext` |
| **行为决策类型** | **`comfort_user`** | **`reflect_origin`** |
| **行为优先级** | **100** (最高优先级 `CRITICAL_CARE`) | **60** (`EMOTIONAL_EXPRESSION`) |
| **工具调用许可** | `allowToolExecution: false` | `allowToolExecution: false` |
| **决策原因** | 检测到用户表达身体不适或负向情绪，仲裁为最高优先级的关怀抚慰行为。 | 检测到关于失熵症或机甲驾驶员身世的讨论，仲裁为沉思回忆行为。 |

## 7. 六大解耦与安全边界

1. **不直接调用 Live2D**：行为决策层只输出 `type: BehaviorType` 与 `multimodalIntent`，不硬编码 Live2D Action ID；
2. **不直接调用 TTS**：声学合成交由后续 Embodiment 统一根据 `multimodalIntent.voice` 调制；
3. **不直接执行工具**：工具执行继续由 `ToolExecutionEngine` 统一受权调度；
4. **不使用 `Math.random()`**：100% 确定性仲裁规则；
5. **不依赖桌宠数值养成**：彻底剥离好感度、饱食度、精力值等旧数值系统；
6. **不修改 Persona / Relationship / MemoryStore**：保持真源架构稳定。
