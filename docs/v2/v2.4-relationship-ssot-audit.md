# Firefly-Agent V2.4: 人际关系真源审计报告 (Relationship SSoT Audit)

- **版本基线**: Firefly-Agent V2.4 (`firefly-v2.4-alpha1`)
- **审计日期**: 2026-09-01
- **审计目标**: 彻底消除 `relationship-registry.ts` 中的硬编码关系事实，确立以 `resources/knowledge/facts.yaml` 和 `resources/knowledge/curated_cards/` 为 **唯一绝对真源 (Single Source of Truth)** 的动态 Relationship 加载与运行时架构。

---

## 1. 架构问题诊断与目标架构

### 1.1 现状诊断 (Dual Source of Truth 问题)
在初始实现中，`src/main/character/relationship-registry.ts` 内部静态维护了 `CANONICAL_RELATIONSHIPS` 对象，直接在 TypeScript 代码中硬编码了流萤与开拓者、卡芙卡、银狼、刃、艾利欧等角色的：
- `attitude`（主观态度阐述）
- `canonicalFacts`（官方事实字符串数组）
- `addressing`（称谓规则）
- `evidenceSources`（来源路径字符串）

这与仓库现存的官方语料真源产生了双重维护：
- `resources/knowledge/facts.yaml`（已定义银狼、卡芙卡、刃、艾利欧、开拓者、知更鸟、黄泉、加拉赫、黑天鹅、翡翠、花火、帕姆的事实与来源）
- `resources/knowledge/curated_cards/`（已定义《初次相遇》、《秘密基地》、《星核猎手同伴》、《黄泉对话》等专属卡片）

### 1.2 目标真源流动架构 (Target SSoT Flow)

```text
       [ Canonical Corpus (唯一真源) ]
        ├── resources/knowledge/facts.yaml (同伴与亲历事实)
        ├── resources/knowledge/curated_cards/ (初遇、秘密基地、星核猎手等卡片)
        └── resources/firefly.yaml (称谓偏好与语言规则)
                       │
                       ▼
            [ RelationshipLoader (动态加载器) ]
             · 解析 facts.yaml 中 entity 事实
             · 关联 curated_cards 专属卡片
             · 动态生成 CharacterRelationship 对象
                       │
                       ▼
            [ RelationshipRegistry (内存运行时) ]
             · 维护 CharacterRelationship 映射表
             · 提供 isKnownCompanion / findRelationship / queryRelationshipPerspective
                       │
                       ▼
            [ CharacterPolicyEngine ]
             · buildSystemPrompt() 动态投影
             · isCanonicalProtected() 动态防篡改
             · classifyIntent() 动态意图路由
```

## 2. 关系数据的三类边界分类 (Data vs Runtime vs Safety)

| 属性 / 逻辑 | 分类 | 归属与处理方式 | 判定规则 |
| :--- | :--- | :--- | :--- |
| **角色名称 (`name`)** | A. Canonical Data | 从 `facts.yaml` 的 `entity` 字段动态提取 | 官方人物名（如“开拓者”、“卡芙卡”） |
| **关系事实 (`canonicalFacts`)** | A. Canonical Data | 从 `facts.yaml` 的 `fact` 字段与 `curated_cards` 动态聚合 | 严禁在 TS 中硬编码第二份事实列表 |
| **证据来源 (`evidenceSources`)** | A. Canonical Data | 从 `facts.yaml` 的 `verified_against` / 文件路径动态生成 | 追溯实际语料物理文件 |
| **主观态度 (`attitude`)** | A. Canonical Data / Derived Presentation | 基于从真源加载的事实动态组装与表达 | 不得脱离官方事实自造臆断 |
| **称谓规范 (`addressing`)** | A. Canonical Data / Derived Presentation | 结合 `firefly.yaml` 称谓偏好与角色尊称规则动态派生 | 如「开拓者」、「卡芙卡」、「帕姆」列车长 |
| **关系层级 (`category`)** | B. Runtime Logic | 由 TypeScript 运行时分类规则判定 (`core_companion`, `stellaron_hunter`, `penacony_contact`, `world_figure`) | 程序结构逻辑 |
| **熟识判定 (`isKnownCompanion`)** | B. Runtime Logic | 由 `RelationshipRegistry` 查表结果判定 | 存在对应官方关系事实即为已知 |
| **视角引导 (`perspectiveGuidance`)** | B. Runtime Logic | 根据 `category` 动态拼接第一人称态度提示 | 提示词程序模板 |
| **防篡改与不可变保护 (`isCanonicalProtected`)** | C. Safety Logic | 提取已加载实体的名称与关系关键词，拦截对抗性改写 | 通用安全防御逻辑，不硬编码具体情节 |
| **防编造硬约束 (`boundaries.canFabricateSharedPast`)** | C. Safety Logic | 固定为 `false`，约束任何人物均不得伪造未经官方记载的共同经历 | 核心安全护栏 |
