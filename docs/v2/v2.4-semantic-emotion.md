- **版本基线**: Firefly-Agent V2.4 (`firefly-v2.4-alpha1`)

## 2. Canonical YAML 规则与 SemanticEmotion 双向映射

在 [`resources/persona/firefly.yaml`](file:///e:/Google-Antigravity/working/Firefly-Pet/resources/persona/firefly.yaml) 中定义了 7 项权威情绪规范（`daily_mode.emotion_rules`）。运行时通过双向映射表实现类型安全与语义清晰：

```typescript
export const CANONICAL_TO_SEMANTIC_EMOTION_MAP: Record<CanonicalEmotionKey, SemanticEmotion> = {
  neutral: "neutral",      // 平淡自然、轻声
  happy: "happy",          // 温和欣慰、暖意
  shy: "shy",              // 羞涩拘谨、轻微停顿
  thinking: "thinking",    // 专注沉思、理清线索
  surprised: "surprised",  // 轻微意外、好奇
  sad: "concerned",        // 对应 YAML sad: 伤感时停顿、轻声、话变少，静静说出关切与守护
  angry: "determined",     // 对应 YAML angry: 极少生气，涉及保护重要之人时展现坚定与稳重
};
```

### 映射原理解析
1. **`sad` $\leftrightarrow$ `concerned` (关切担忧)**：
   - YAML 原文：“伤感时表现为停顿、轻声、话变少——不会失控，只是静静地说出感受”；
   - 在交互语境中，当用户遇到困难、痛苦或流露疲惫时，流萤的心境即为此类温柔克制的心疼与主动关怀（`caring`），既体恤对方又静静守护。
2. **`angry` $\leftrightarrow$ `determined` (认真坚定)**：
   - YAML 原文：“极少生气，仅在涉及保护重要的人时展现坚定——声音变低变稳”；
   - 流萤从不会无端暴怒或对同伴发脾气，所谓的“angry”在流萤身上即为**保护姿态下的严肃、坚定与果决**（在工作模式或守护任务时激活）。

## 3. 彻底去除运行时硬编码 Persona Prose (SSoT Guarantee)

为避免在 TypeScript 运行时维护第二份 Canonical Persona 描述，`SemanticStateInterpreter` 做出以下严格治理：
1. **删除** 代码中硬编码的“语气轻快柔和…”、“拘谨害羞…”、“声音变低变稳…”等派生散文；
2. **完全由 `PersonaLoader.getProfile()` 动态解析**：
   - `expressionGuidance`: 直接读取 `profile.dailyMode.emotionRules[canonicalEmotion]` 或 `profile.workMode.tone.description`；
   - `behavioralTendency`: 直接读取 `profile.vocabulary.speakingHabits` 或 `profile.workMode.characteristics`；
3. **测试保障**：在静态测试中全量扫描 `semantic-state-interpreter.ts`，确保 0 违规硬编码。

## 4. 严格区分“外部用户不适”与“流萤自身病理/身世”

| 维度 | 外部用户不适 (User Distress) | 流萤自身病理/身世 (Self Physical / Entropy Loss) |
| :--- | :--- | :--- |
| **触发关键词** | “我头疼/我累了/我生病/我好难过/救救我” | “失熵症/身体解离/医疗舱/格拉默铁骑/AR-26710” |
| **语义情绪** | **`concerned`** (对应官方 `sad` 规则) | **`thinking`** (沉思) / 工作态 **`determined`** |
| **认知上下文** | **`caring`** (主动关怀与体贴抚慰) | **`reflecting`** (深度身世回忆与生命思考) |
| **心境起因** | 感知到对方的不适或困扰，由衷表达关切与守护 | 探讨自身失熵症宿命与机甲经历，流露对当下生活的珍视 |

## 5. 语义内在状态契约 (SemanticInnerState)

```typescript
export interface SemanticInnerState {
  /** 运行时语义情绪 */
  readonly emotion: SemanticEmotion;
  /** 1:1 对应的 Canonical YAML 情绪键 */
  readonly canonicalEmotion: CanonicalEmotionKey;
  /** 当前认知 / 行为上下文 */
  readonly cognitiveContext: CognitiveContext;
  /** 当前模式 (日常 / 工作态) */
  readonly mode: CharacterMode;
  /** 情绪起因解释 (为什么是这个心境，具备完全可解释性) */
  readonly explanation: string;
  /** 语言表达倾向指引 (直接来源于 PersonaLoader 读取的 firefly.yaml) */
  readonly expressionGuidance: string;
  /** 行为姿态倾向 (直接来源于 PersonaLoader 读取的 firefly.yaml) */
  readonly behavioralTendency: string;
  /** 评估生成时间戳 */
  readonly timestamp: number;
}
```

## 6. 四大核心架构边界与不变性保障

1. **Persona 不变性 (Persona Invariance)**：
   - 情绪是瞬时心境，人格是长久底色；
   - 任何情绪变化**绝对禁止修改 `PersonaProfile`、`firefly.yaml` 或角色核心价值观**。
2. **Relationship 不变性 (Relationship Invariance)**：
   - 关系提供“我正在和谁交流”，情绪提供“我现在的心境”；
   - 情绪波动**绝对不会篡改已建立的官方同伴关系事实**。
3. **Memory Store 不变性 (Memory Invariance)**：
   - 本阶段仅只读检索 Memory 上下文辅助情绪判定；
   - 情绪解释器**绝对不会向 `MemoryStore` 自动写入任何记忆记录**。
4. **旧数值状态解耦 (Numeric State Independence)**：
   - 核心语义情绪判定完全脱离 `affection`、`hunger`、`energy`、`health`、`attention` 数值；
   - 保持现有 UI/IPC 兼容层的平滑运行，但不允许数值污染大语言模型认知。

## 7. System Prompt 结构化投影

在 System Prompt 中，内在状态被投影为高语义、低 Token（~100 Tokens）的标准段落：

```markdown
【当前内在状态】
- 当前心境：温和欣慰（happy，对应官方规则：happy）
- 认知上下文：分享记忆
- 运行模式：日常陪伴模式
- 心境起因：提及喜爱的食物、美好回忆或重聚时光，心生暖意与欣喜。正在与最珍视的开拓者交流，语气自然亲近、多一份柔软。
- 表达倾向：不是外放大笑型——你开心时会轻轻地柔和下来，语气里多一分暖意
- 行为倾向：用'我'自称，永远不用'流萤''萨姆''她'等第三人称称呼自己；称呼亲近的人时会带着温度
```
