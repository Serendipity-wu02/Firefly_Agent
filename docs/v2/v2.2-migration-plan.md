# Firefly-Agent V2.2: Memory v2 迁移与实施方案 (Migration Plan)

- **版本**: V2.2 Migration & Implementation Plan
- **状态**: READY FOR IMPLEMENTATION
- **目标**: 将 Firefly-Pet 从扁平正则 key-value 记忆系统 (Memory v1) 平滑、无损地演进至分层结构化记忆系统 (Memory v2)，确保现有数据 100% 继承，已有测试与接口契约 100% 保持兼容。

---

## 1. 迁移路线与阶段拆解 (Phased Rollout)

```text
┌─────────────────────────────────────────────────────────────┐
│ Phase 1: 数据模型与基础存储层 (Core Models & Store)          │
│ - MemoryEntry, EntityNode, RelationEdge, Preference 模型    │
│ - IMemoryStore 接口与 JsonFileMemoryStore (原子写入/WAL)    │
│ - V1 数据自动迁移加载器 (V1ToV2Migrator)                    │
├─────────────────────────────────────────────────────────────┤
│ Phase 2: 提取引擎、写入策略与冲突消解 (Extraction & Policy) │
│ - MemoryWritePolicy (闲聊过滤、高价值事实准入)              │
│ - Fact & Preference Extractor (结构化提取器)                │
│ - ConflictResolver (时间覆盖、偏好演化、矛盾反转)           │
├─────────────────────────────────────────────────────────────┤
│ Phase 3: 混合检索、排序与上下文投影 (Retrieval & Projection)│
│ - HybridMemoryRetriever (实体匹配 + 文本相关 + 重要性 + 衰减)│
│ - MemoryProjector (基于 Token 预算的精简格式化)             │
│ - MemorySlot 适配对接                                       │
├─────────────────────────────────────────────────────────────┤
│ Phase 4: 记忆巩固与半衰期衰减 (Consolidation & Decay)       │
│ - DecayEngine (艾宾浩斯指数半衰期、存活修剪)                │
│ - MemoryConsolidator (L0→L1 沉淀、L1→L2 频次升格合并)       │
├─────────────────────────────────────────────────────────────┤
│ Phase 5: 门面适配与全系统端到端集成 (Facade & Integration)  │
│ - FireflyMemoryService 适配器封装 (100% 兼容 V1 契约)       │
│ - FireflyAgentCore 与 ProactiveScheduler 对接                │
│ - 全量单元、集成与 Python 回归测试验证                      │
└─────────────────────────────────────────────────────────────┘
```

## 2. 遗留数据迁移方案 (Legacy Data Migration)

### 2.1 格式映射对照表
| V1 字段 (`config/memory.json`) | V2.2 字段 (`config/memory_v2.json`) | 转换逻辑 |
| :--- | :--- | :--- |
| `key: "用户名字"` | `category: "profile"`, `key: "user_name"`, `importance: 0.95` | 固定画像映射，`pinned: true` |
| `key: "用户生日"` | `category: "profile"`, `key: "user_birthday"`, `importance: 0.95` | 固定画像映射，`pinned: true` |
| `key: "用户喜好"` | `category: "preference"`, `key: value`, `importance: 0.8` | 生成 Preference 记录 (`polarity: "like"`) |
| `key: "用户忌讳"` | `category: "preference"`, `key: value`, `importance: 0.9` | 生成 Preference 记录 (`polarity: "dislike"`, `intensity: 5`) |
| 自定义 key | `category: "entity"`, `key: key`, `importance: 0.5` | 默认通用实体与事实 |

### 2.2 无损自动迁移机制
1. 初始化 `MemoryManager` 时，若检测到 `config/memory_v2.json` 不存在但 `config/memory.json` 存在：
   - 读取并解析 `config/memory.json`；
   - 自动映射并转换为 `MemoryEntry` 数组；
   - 原子写入 `config/memory_v2.json`；
   - 将原 `config/memory.json` 自动备份为 `config/memory.v1.bak.json`，确保数据零丢失。

## 3. 向后兼容性保障 (Backwards Compatibility)

1. **Facade 门面兼容**:
   - `FireflyMemoryService` 将作为 `MemoryManager` 的轻量封装门面，保留原有方法签名：
     - `remember(key, value, source)` $\rightarrow$ 映射为 `memoryManager.remember(...)`
     - `forget(key)` $\rightarrow$ 映射为 `memoryManager.forget(...)`
     - `get(key)` $\rightarrow$ 映射为 `memoryManager.get(...)`
     - `list()` $\rightarrow$ 映射为 `memoryManager.list(...)`
     - `buildMemoryContext(query)` $\rightarrow$ 映射为 `memoryManager.buildContext(query)`
2. **测试兼容**:
   - `test_firefly_agent_core_v1.mjs` 中的 `memoryService` 调用无需修改任何一行代码即可 100% 跑通；
   - `tools/validate_persistence.py` 读写 `memory.json` 的契约通过双写机制保持完全兼容。

---

## 4. 回滚方案 (Rollback Plan)

若在实施过程中出现异常：
1. **降级开关**: `MemoryManager` 支持 `useV1Engine: true` 配置，可瞬时回退至 V1 纯内存 Map 引擎；
2. **数据回滚**: 可直接将备份的 `config/memory.v1.bak.json` 恢复为 `config/memory.json`。
