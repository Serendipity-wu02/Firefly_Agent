# H historical retrieval and independent migration: next implementation plan

Status: original proposal; approved follow-up implementation and binding refinements are in `2026-10-02-memory-h-isolated-implementation.md`. The original proposed raw weighting and preview/apply wording below are superseded by that plan; no H implementation, production installation, data migration, provider request or dependency change in this branch. S remains recent context and source-backed summaries; M remains long-lived valid facts; H remains historical conversation retrieval. The approved M plan is `2026-10-01-memory-recall-implementation.md`.

## Verified existing interfaces and why direct reuse needs boundaries

- `src/main/rag/retriever.ts`: `new Jieba()` from `@node-rs/jieba`, `cut(text,true)`, `tag(word,true)`; tokenizer is private. `registerJiebaCustomWord(s)` maintains post-merge names; `HybridRetriever(store,provider).retrieve(query,source?,topK=5,options={},vectorWeight=.7,bm25Weight=.3)` accepts `importIds`/`allowedEntryIds` and returns `SearchResult[]`. These weights are existing RAG behavior, not approved H defaults.
- `src/main/rag/vectorstore.ts`: active `JsonVectorStore(dbPath)` reads plaintext `memory-store.json`/metadata. `search(query,source?,provider?,topK=5,minScore=.3,options={})` updates selected `lastRecalledAt` and weight and schedules a save. `add(text,source,provider,metadata?)` can deduplicate via that mutating search; it also updates timestamps/weight. This cannot supply canonical M usage or an encrypted H repository. Do not invoke it on production data or wrap its side effects under renamed classes.
- `src/main/rag/embedding.ts`: `EmbeddingProvider.embed(text):Promise<number[]>`, `embedBatch(texts):Promise<number[][]>`, `dims`, `name`, optional `cacheIdentity` (`provider/model/dimensions/endpoint`), `declaredDimensions`/`resolvedDimensions`, `workerConfig`. Local model configuration currently names bge-m3; no model is downloaded or called by this stage. `@lancedb/lancedb` is a dependency, but the inspected active RAG vector path above is JSON; do not describe LanceDB as the installed new memory index.
- `src/main/rag/index.ts::initRAG` obtains global userData/model/worldbook paths. The independent test adapter must not call this bootstrap. Use explicitly injected E: roots and synthetic providers. Keep existing RAG behavior and modified application Skills unchanged.
- M canonical seams now exist: `PolicyRepository.eligibleFactsWithinTransaction`, `RecallRepository.visibleFactsWithinTransaction`, worker-owned visibility dependencies and Main pending-use confirmation. H/vector indexes may nominate IDs/revisions only; canonical support/suppression/visibility and final S claim decide whether M may be injected.

## Proposed isolated interfaces

1. New `history-contracts.ts`: `HistoryDocumentRef {documentId,revision,actorKey,sourceRefs}`, `HistoryHit {documentRef,span,role,score,channel}`, `HistoryQuery {actorToken,query,limit,signal}`. These are proposed names, not existing APIs. Scopes and provider/session authorization come from Main capability, never model-supplied scope/ownership. Spans refer to current verified source/transcript messages; role, time and source attribution are mandatory. Retrieved history is quoted evidence, not an explicit user event or automatic fact confirmation.
2. `HistoryRepository`: encrypted canonical history document/chunk/version metadata in SQLite worker, source heads/suppression dependencies and derived ancestry checked in its transaction. Index records store rebuildable encrypted terms/vector metadata, model identity/dimensions, and canonical document IDs/revisions. No plaintext JSON copy, legacy recall weight, M access refresh or model text in receipts. New schema/version/actual old-writer fixture only after architecture review.
3. `HistoryIndex.search` is a read-only nominated-ID interface. Extract a pure testable Jieba token helper from the actual tokenizer while preserving existing RAG output; add an injected lexical/BM25 adapter. Implement a separate side-effect-free vector adapter with finite dimension checks, model-identity binding and normalization. Reuse `EmbeddingProvider` contract by dependency injection, not global `getEmbeddingProvider` bootstrap. First tests use deterministic synthetic vectors; semantic quality is not inferred from them.
4. Main historical query: authorize -> current canonical readable sources -> lexical/vector candidate union -> deterministic dedup/fusion -> recheck each canonical revision/source/suppression -> return attributed history hits. Explicit archived-M inspection remains separate from automatic normal-M injection. Capture final retrieval dependencies before budget preparation; recheck them at final claim so stale index, delete/edit/forget/correct cannot revive an old assertion or hidden history.
5. Independent migration seam: parse a documented exported Firefly input into versioned canonical records using new code. `preview` produces counts, provenance gaps/conflicts and an opaque Main apply capability; `apply` validates immutable import digest/current generation and uses bounded idempotent transactions. Preserve original export and complete DB/auth/protected-key metadata backups. Invalid/untraceable/derived historical text cannot become supported M; quarantine/report it. Do not read another product's installed data or reuse its writer. Do not run against current real userData during implementation.

## Implementation order and required tests

1. Pure tokenization/ranking: UTF-8 Chinese/English/mixed strings, custom entity merge/version invalidation, empty/punctuation-only, determinism, finite vectors/dimension/model mismatch, stable tie ordering and cancellation. Verify the old RAG tests remain unchanged; no new dependency/CI threshold.
2. Encrypted H repository: actual prior writer -> additive schema; auth/future/fault byte proof, process reopen, chunk revision/span bounds, tool-call/result completeness and attribution, receipt encryption/no bodies, duplicate import/different digest conflict and full rollback. Source delete/edit/recreation, suppression and derived roots invalidate hits even with a stale index.
3. Hybrid Main seam: actor/session isolation, fake/temporary capabilities, ID-only index poison, BM25-only when vector capability is absent, deterministic union/dedup, canonical pre-budget + pre-send revalidation and network-free synthetic E: integration. Rank/scan/preview never update M access; only current M actually used by the local sender follows the existing ticket protocol.
4. Synthetic migration: sanctioned Firefly export fixtures with direct-user/assistant/tool/derived/source-invalid and conflicting revisions. Preview makes no canonical truth writes; apply is bounded/cancellable/idempotent; lost receipt/restart cannot duplicate rows or revive forget. Verify provenance/license inventory independently of runtime behavior; do not copy/rename the legacy implementation.
5. Fresh whole-range review, exact final HEAD full/related/types/build/related packaging and hidden synthetic development/ASAR create/reopen/rollback. Native Jieba/embedding bindings require actual installed-version verification. No physical crash/power-loss claim without a separate test.

## Real provider counter evaluation before any production cutover

The current probes' counter is JSON body length and is exact only for their synthetic fixture, not a provider tokenizer. Obtain an authorized real provider/model capability and fixed framing version first. Build request fixtures including system/developer/user/assistant, tool schemas/tool results, source citations, cache headers/segments and supported image/audio inputs; count the entire immutable prepared request, compare to authoritative provider usage, record framing identity and reject unsupported input/capability changes. Include reserved output, input/context limits, safety margin and negative tests for unknown limits/estimates. No fallback 256k/8192 assumption. Account/API requests remain unexecuted until specifically authorized; cache/schema/framing changes invalidate prepared budgets.

## Cutover, rollback and decisions

All new seams remain uninstalled until the parent approves the concrete next implementation and, later, an explicit production switch. Stage gates: disabled -> dry-run reports -> enabled synthetic maintenance/query -> optional isolated canary -> approved production caller/writer. H data/index root is separate and writer ownership remains singular. Stop writers before backup restoration. Old v7 code intentionally refuses v8; restore a complete known-good v7 DB/auth/key/profile backup into an owned matching root and open with the actual v7 writer. Never downgrade by dropping recall/context tables or resetting user_version. A later v9 cutover needs its own old v8 backup proof.

Open product decisions for H: permitted cross-session/provider history scope; which role/time-attributed excerpts the user expects; default retrieval limit and fusion weights derived from representative evaluation, not copied .7/.3; optional vector capability/model/storage budget and explicit archived inspection UX; supported sanctioned export formats and conflict/quarantine review UX. These do not block the already approved M completion, and are not permission requests to redo it.
