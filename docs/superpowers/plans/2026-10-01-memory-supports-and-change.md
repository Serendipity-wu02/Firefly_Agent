## Commit 1: source-backed support sets

- Add worker-only encrypted fact_supports and fact_reviews in schema v6. Support binds actor/scope, factId + immutable factRevision, exact BoundSourceRef, acceptance kind and trusted event target/revision/nonce. Metadata contains no quote or source body. Same origin/version never counts as independent copies; policy acceptance never becomes a user-confirmation flag.
- Main private APIs: recall(actor) returns only eligible current M; audit(actor,factId) returns support/review metadata without source/assertion text; reconcileSupports(actor) rechecks ledger heads transactionally. Existing core current/history remain low-level diagnostic APIs, not support-aware product recall. No production caller is switched.
- Tighten synthetic confirm events: candidateId/revision/nonce plus an independently captured direct-user confirmation SourceRef; confirmFact binds factId/revision for adding an independent source-backed confirmation to an existing fact. The Main action is explicit; chat/model text alone cannot mint it. Confirmation source/version is rechecked at commit and on recall. A confirm source with the same sourceId as the original candidate evidence is rejected. Reject remains distinct from deny: a new trusted deny event binds factId/revision/source, marks review without forget or destroying history.
- Equivalent direct preference input adds an independent automatic support to the existing revision, not a new current fact or a last-arrival overwrite. Source validity is computed from every bound head; pending/stale/deleted/recreated heads cannot support recall. Sole invalid support yields pending-review; any independent valid support can preserve recall. Explicit denial yields review even with old supports.
- Explicit correction adds a new assertion revision and its own direct source-backed support. Old support links remain metadata tied to old revisions. Explicit forget suppresses all links/reviews and adds their source refs to core suppression origins; new support, maintenance retry, alternate source or another generation cannot reopen old facts. Remember still requires B2 fresh source/event generation; fresh remembered facts have new supports, old links stay suppressed.
- v5 synthetic databases upgrade additively/transactionally. Legacy B2 automatic facts may bootstrap a single automatic link from their durable bound source. Legacy synthetic explicit confirmations without a verifiable independent bound confirmation source remain pending-review until a new confirmFact event. Never infer trust from old role/displayName/checkbox. No immutable fact payload rewrite.

Acceptance: sole vs multiple automatic supports; live/stale/deleted confirmation; independently confirmed imported preference; duplicate origin not multiple supports; edit/delete/recreate; explicit denial separate from correction/forget; audit lacks deleted message body; concurrent reconcile/forget/late jobs; cross-actor/scope; reopen; v3/v4/v5 fixture migration and failed-v5 rollback/future refusal. Re-run B2 captured-before-forget and refresh_token/passphrase/body/log privacy tests explicitly.

## Commit 2: narrow clear-change integration

- Add private integrate(actor,BoundSourceRef) and deterministic maintenance grammar. Worker revalidates exact full source and normalization. Actor and subject/attribute/context/cardinality come from Main deterministic parsing, never model fields.
- Context keys default/work/personal, deterministically extracted from source. Default preserves the existing B2 subject identity; other contexts generate different normalized subject keys. Programming-language usage supports multiple values; work Python and personal Rust coexist, and additive abilities are not contradictions. Ambiguous/context-unknown text stays reference-only candidate.
- Source observations gain optional provider-owned occurredAt; absent means unknown, never replaced by transaction/record time. Source provider revision changes when occurrence metadata changes; preserved binding/fingerprint checks remain. New clear-change statements require explicit current change, unambiguous actor/context/attribute and ordered known source time, single-valued attribute, valid support and expected current revision. Append sourced/timed revision via core correct and preserve prior assertion/support history. Manual corrections and forget/generation barriers defeat captured/queued stale automatic work.
- Same-value claims deduplicate support. Unmarked contradiction, quote/hypothesis/inference/sensitivity, unknown time, out-of-order/equal source time and future-effective claim stay candidate. Future claims are not activated by an unimplemented scheduler. Explicit source-backed denial creates review, not forget/hard deletion. Multi-value updates remain additive without silently removing prior values.

Acceptance: clear current change appends/supersedes; unmarked ambiguous contradiction does not; historical source arrives late; equal/unknown time; future-effective date; concurrent integrate/correct/forget/reconcile; cross-scope/context, work Python vs personal Rust; multi-value additions; source epoch remember regressions. Retain >=60 named Chinese/English/emoji deterministic rows and label real-model evaluation unperformed.
