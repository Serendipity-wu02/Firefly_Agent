## 用户反馈

有多位用户反馈“昔涟主动聊天没有正常工作”或“没有主动找我聊天”。目前缺少稳定的复现步骤、具体版本、发送目标和失败时的日志，暂时无法确认问题发生在候选生成、模型请求、消息投递还是用户可见性。

## 当前结论

暂未确认主动聊天核心链路存在普遍性代码 Bug。

存在一个需要单独继续验证的可疑用户体验问题：本地投递路径主要是写入专用会话并广播会话变化；当前 React 聊天页可能保留用户正在查看的会话，且旧版桌宠气泡/未读提示已不再存在。因此消息可能已经成功落库，但用户没有收到明显提醒。这是“消息生成成功但用户未看到”的候选解释，尚不能作为本 issue 的已确认根因。

另有两个已知但尚未证明与用户反馈直接相关的风险点：

1. 夜间策略使用运行机器本地小时，而候选生成使用用户配置时区；跨时区用户可能出现误拦截或误放行。
2. `back_from_away` 的返回事件依赖扫描周期内的空闲边沿，用户刚开启开关或返回操作时可能错过该边沿。

## 待收集信息

每个用户案例至少需要：

- 应用版本及开发版/安装包渠道；
- 主动聊天开关和投递目标（本地、微信、飞书）；
- 触发前是否连续操作电脑、是否刚从长时间离开回来；
- “没有主动聊天”是没有生成、没有弹出提醒，还是只在会话列表中找不到；
- `proactive-state.json` 中的 `lastProactiveAt`、`lastProactiveScene`、`lastFiredAt`；
- 打包版的 `userData/logs/cyrene.log`（当前主动聊天部分使用 `console.log`，可能不会落盘）。
