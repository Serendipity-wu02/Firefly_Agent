# 给本地 Codex / Antigravity 的执行交接

用户目标：在自己的 Firefly_Agent 中，从原作者上游重新获取旧快照对应的 39 项技能，而不是再复制 Cyrene 的整个技能快照。保留现有能力、用户修改、禁用状态和审批边界。

## 已发生和未发生

远端读取基线是 `35457af3279fccaf0ab462f8744f47183fce79f1`。本轮创建分支被 GitHub 连接以 403 拒绝；没有远端提交或 PR，也没有修改本地项目。本包不含上游技能源码；只能在可联网的环境执行获取工具后产生实际源码。24 项通过的是工具的离线夹具测试，不是联网下载或 Firefly 运行时测试。

## 执行顺序

1. 在用户当前项目检查 Git 状态、分支、未提交修改、当前扫描器、注册表、加载工具、效果分类、模式覆盖、快照构建及托管更新逻辑。使用实际本地版本，不用这里的旧远端版本覆盖用户修改。不要重置、清理、自动合并或推送主分支。
2. 将获取工具放在项目内合适的工具目录。运行 `fetch_skills.py --plan`，然后执行 `--project <实际根目录> --fetch`。用户要一并保留办公候选供审阅时，加 `--include-office-candidates`。只读取原作者上游，不拿 Cyrene 快照充当本次新获取来源。
3. 检查 `receipt.json`，逐项核对真实下载状态、固定提交、许可证原文与哈希、缺少的本地引用。发现未知嵌套许可证、Git LFS、符号链接或来源缺失时，不移除校验硬凑数量。先解决原因；保留错误证据，旧技能继续不动。
4. 清单分为 35 条获取路线、2 个办公候选、2 项未定位。PDF/XLSX 候选不是已证明相同的原版；`office-design` 与 `write-expense-report` 不能因为旧快照将它们归入三方就推定存在独立上游。不要用无关同名技能替代，不要把保留旧版计为“重新获取成功”。没有明确来源时，记录待办，不重写技能来伪造 39 项完成。
5. 在隔离分支中逐项适配取得的源。保持旧 Skill ID 与上游名称之间的显式映射；上游原文和归属单独保留，Firefly 适配层单独标明。源码刷新允许版本变化，不代表原改造逻辑被上游包含。
6. 读取真实宿主契约后再填写 `effectKind`、`tools`、`modes` 和 manifest。清单里的 suggested_modes_for_review 只是复核提示，不是已核验的本机状态，不直接写进运行配置。不要把 Code 技能全改为 Work；不要把 `allowed-tools` 当作授权；不因为加载技能而扩大沙盒或审批权限。
7. 确保 `as-` / `ecc-` / `sp-` 的交叉调用名称可解析。补齐正文、references、scripts、模板和平台说明的真实读取路径；审阅源中对 Skill/Task/子代理/浏览器/外部 CLI 的假设。宿主没有的能力明确报缺，不能伪造工具。未审阅的 hooks、安装脚本、网络命令一律不自动执行。
8. 保留旧文档工作流的 Windows 适配、`write_word` 等既有快捷路由和用户数据保护。源获取不能证明重算、PDF 渲染、.NET、PptxGenJS、LibreOffice 或模型行为已可用，分别核对实际依赖和运行测试。
9. 逐项通过宿主扫描/注册、模式过滤、效果分类与审批、正文/附件续读、输出验证，再决定是否纳入项目正式快照。用户旧设置优先；已有用户覆盖目录和修改文件先比对与保护。不能直接覆盖整个 userData/skills，也不能移除当前 39 项或 8 项内置技能作为“清理”。
10. 按实际版本的更新机制制作可回滚的替换，保留上游许可证、作者和版本记录。先运行相关原生测试、类型检查、构建与回归，验证失败不删除测试、不扩大权限、不报告全部成功。

## 最终汇报必须区分

来源已定位、源码已取得、静态完整性通过、Firefly 适配完成、真实模型/Windows 行为通过、已启用、仍保留旧版、未定位/许可未确认，分别计数。

报告实际新增和修改的文件、源提交、验证命令与退出码。不要把本工具生成目录、下载了一个 SKILL.md、读了来源 README 或 24 项夹具测试，写成“39 个技能已经全部重新获取并安装成功”。
