# Firefly：45 Skills 与 12 个子代理分配

日期：2026-10-06。基于已交付源码 c29485a。

每个 skill 只有一个主责。协作者可共享使用；五项全员协议不重复计入主责数量。角色设定只用于表达和分工意象，工程能力来自工具和实现，不能由角色设定扩大权限。

本次不改角色 ID、模型配置或工具授权。Work 保留 12 人，Code 保留原有 11 人；Chat 不派生子任务。费用报表保持 Work 模式。

## 艾利欧：战略与规划（主责 3 项）
目标优先级、任务拆解、依赖与执行计划；协调安排由卡芙卡汇总后交主代理决定

- `as-planning-and-task-breakdown`：把明确需求拆成可执行任务，标明顺序、依赖、范围与并行机会。协作：姬子、卡芙卡。
- `ecc-plan-canvas`：组织计划与可视产物评审；交互画布需另行安装并授权，未具备时用会话收集反馈。协作：三月七、姬子。
- `sp-writing-plans`：把已确认规格写成可逐步执行的实现计划，列明文件、测试与验收步骤。协作：姬子、刃、卡芙卡。

## 姬子：架构与集成（主责 2 项）
规格、模块边界、API 与系统集成；将计划转成一致的技术契约

- `as-api-and-interface-design`：设计稳定的 API、模块边界与类型契约，明确前后端交互接口。协作：刃、瓦尔特、星期日。
- `as-spec-driven-development`：在编码前澄清需求，形成边界、行为与验收标准明确的规格。协作：艾利欧、瓦尔特。

## 刃：代码实现（主责 4 项）
代码实现、重构、修复与 TDD

- `tob-property-based-testing`：编写、审查和调试属性测试，用生成式输入检验不变量与往返转换等规则。协作：瓦尔特、星期日。
- `as-code-simplification`：在保持行为不变的前提下简化代码，提升可读性与可维护性。协作：瓦尔特、三月七、银狼。
- `as-incremental-implementation`：将较大改动拆成可验证的小步，逐步实现、测试和集成。协作：姬子、三月七、银狼。
- `ecc-tdd-workflow`：先写失败测试，再实现与重构，保留单元、集成和端到端验证证据。协作：瓦尔特、银狼、三月七、卡芙卡。

## 大黑塔：技术研究（主责 3 项）
候选方案探索、源码资料研究、假设质疑与实验验证；研究兴趣不替代任务验收标准

- `as-doubt-driven-development`：对重要决策做反向质疑并核验证据，独立复核由主代理协调。协作：瓦尔特、姬子、星期日。
- `as-source-driven-development`：核对实际依赖版本与官方资料，为实现决策提供可追溯依据。协作：丹恒、姬子、刃、银狼。
- `sp-brainstorming`：在实现前澄清用户意图、需求与约束，比较方案并确认设计。协作：艾利欧、姬子、三月七。

## 丹恒：知识管理（主责 5 项）
源码事实、代码库理解、Memory/RAG 与知识整理

- `knowledge-workspace`：在 Work 知识任务中安全读取、定位和维护 Obsidian 笔记。协作：大黑塔、知更鸟。
- `as-context-engineering`：按任务整理规则、规格、源码与验证结果，控制上下文冗余和信息缺口。协作：全体其他角色（公共协议）。
- `ecc-code-tour`：生成锚定真实文件与行号的 CodeTour 导览，解释架构、变更或故障原因。协作：姬子、瓦尔特、卡芙卡。
- `ecc-codebase-onboarding`：梳理陌生代码库的架构、入口与约定，形成项目入门指南。协作：姬子、刃。
- `self-improving-agent`：记录纠错、失败、知识缺口与已验证的可复用改进，不改变权限。协作：全体其他角色（公共协议）。

## 瓦尔特：质量审查（主责 4 项）
Code Review、回归质量、可靠性和完成证据核验；独立复核实现结果

- `as-code-review-and-quality`：从正确性、可维护性等多个维度审查代码，识别合并前的质量问题。协作：姬子、星期日。
- `ecc-ai-regression-testing`：为 AI 辅助改动建立回归测试，检查接口契约和沙箱、生产路径差异。协作：刃、大黑塔、卡芙卡。
- `sp-requesting-code-review`：准备需求、改动与验证证据，请求代码审查并处理合并前的阻塞问题。协作：刃、卡芙卡、星期日。
- `sp-verification-before-completion`：在宣称完成、修复或通过前执行相关检查，以实际输出支持结论。协作：全体其他角色（公共协议）。

## 星期日：安全治理（主责 3 项）
安全审查、权限规则、风险与治理边界验收；不能自行扩大任何角色权限

- `as-security-and-hardening`：加固输入校验、身份认证、数据存储与外部集成中的安全边界。协作：姬子、刃、瓦尔特、银狼。
- `ecc-coding-standards`：统一命名、可读性、不可变性与代码审查的基础约定。协作：全体其他角色（公共协议）。
- `ecc-security-review`：用安全清单审查认证、输入、密钥、API 与支付等敏感功能。协作：瓦尔特、姬子、刃。

## 三月七：界面与视觉（主责 3 项）
React、UI/UX、图表、视觉与办公主题；与知更鸟协作统一文档表现

- `diagram`：按 Firefly 主题制作静态 SVG 学习卡片，控制布局、复杂度与信息密度。协作：姬子、丹恒、知更鸟、艾利欧。
- `as-frontend-ui-engineering`：构建可访问、响应式的前端界面，处理组件、布局、状态与交互质量。协作：刃。
- `office-design`：为 Word、Excel、PDF 和演示文稿统一主题、字体、间距与数据语义。协作：知更鸟。

## 知更鸟：文档与数据（主责 5 项）
DOCX/PDF/PPTX/XLSX、报告、表格与数据产物

- `document-reader-validation`：围绕目标读者检查结构与事实，以具体问题验证理解并修订文档。协作：丹恒、大黑塔。
- `docx`：使用 OpenXML 创建、编辑和套用 Word 模板，并校验文档结构与格式。协作：丹恒、大黑塔。
- `pdf`：在 Windows 上创建、检查、填写和调整 PDF，并渲染核验版式。协作：丹恒、大黑塔。
- `pptx-generator`：创建、读取和编辑 PowerPoint，支持新建幻灯片与现有文件的 XML 修改。协作：三月七。
- `xlsx`：在 Windows 上创建、读取、编辑和重算 Excel，保留公式与既有结构并核验结果。协作：大黑塔。

## 银狼：工具、Skills 与技术排障（主责 7 项）
Skills、插件、工具链、自动化与系统化技术根因调查；不绕过授权和安全边界

- `plugin-development`：开发与调试 Firefly 插件的工具、弹窗和渠道接入，不用于本体功能开发。协作：刃、姬子、星期日、帕姆。
- `as-debugging-and-error-recovery`：系统定位测试、构建和运行异常的根因，实施并验证最小恢复措施。协作：刃、卡芙卡、瓦尔特、帕姆。
- `as-using-agent-skills`：发现并选择适用技能，通过现有加载机制按需读取和调用。协作：全体其他角色（公共协议）。
- `ecc-agent-introspection-debugging`：记录代理失败现场，诊断重复调用或任务偏移，执行有限恢复并报告。协作：卡芙卡、大黑塔。
- `skill-creator`：创建和改进技能，通过评测、基准对比与描述优化提高质量和触发准确性。协作：大黑塔、瓦尔特。
- `sp-systematic-debugging`：先复现问题、收集证据和验证根因假设，再修复并做回归检查。协作：卡芙卡、刃、大黑塔、帕姆。
- `sp-using-superpowers`：在任务开始时识别适用技能，按流程选择并调用所需指导。协作：艾利欧、卡芙卡。

## 帕姆：工程运维（主责 4 项）
Git、worktree、CI、构建、打包、发布检查与费用报表事务；只处理已授权资源

- `ecc-production-audit`：依据本地证据审查上线准备度，识别发布风险、阻塞项与修复建议。协作：瓦尔特、星期日。
- `as-git-workflow-and-versioning`：规范分支、提交、冲突处理、版本号与变更记录，组织并行开发和发布。协作：刃、卡芙卡。
- `sp-using-git-worktrees`：核对并建立已授权的隔离工作区，保护现有修改并验证起始基线。协作：刃、卡芙卡。
- `write-expense-report`：按确认范围读取支出，核对币种与金额，汇总分类并生成 Excel 报告。协作：知更鸟。

## 卡芙卡：执行协调（主责 2 项）
并行分工、依赖排序、故障复现安排与升级交接建议；技术根因交银狼、实际委派交主代理

- `sp-dispatching-parallel-agents`：识别无共享状态和顺序依赖的独立任务，向主代理提供并行分工建议。协作：艾利欧。
- `sp-subagent-driven-development`：按已批准计划组织任务实施、规格审查与质量复核，实际委派由主代理执行。协作：艾利欧、刃、瓦尔特。

## 运行边界

- 主责改变不意味着新增工具或批准外部调用；所有工具仍受父会话权限约束。
- 并行调度类 skill 对子代理仅提供编排建议；实际委派由 Firefly 主代理执行，子代理不能递归委派或替用户批准副作用。
- 上游许可证、来源记录、自维护技能内容与45项总数保持原样。
