# 交付①：普通启动 S/M/H 与旧个人记忆链退出

来源：[共同设计与用户验收补充](default-memory-and-parallel-roles-design.md)。先独立交付本项；多角色并行另行交付。

## 2. 默认记忆运行

- 普通启动装配统一 Main 记忆服务，不再依赖 firefly-memory-controlled，不再仅接受默认档案的无工具 Chat。
- S 负责当前会话上下文及摘要；M 负责有来源的长期事实、候选与确认/纠正/遗忘；H 负责可核验历史读取。多轮工具调用和结果必须作为完整单元参与预算、持久化和恢复。
- 桌面 Chat/Work/Code、渠道、定时任务、子角色及主动消息分别使用可信来源适配。渠道按账号、发送者与群聊隔离；不把外部发送者自动当作本地主人。委派指令、计划与模型输出不得写成用户陈述事实。
- 临时会话不读写持久 M/H。非交互任务只在已有授权范围读取。附件保留原有文件权限和出处，不能因启用新记忆而拒绝所有带附件消息或自动永久记住附件内容。
- 使用真实模型档案身份与配置版本，变更后撤销旧请求权限；保留取消、编辑、删除、关闭时的失效与等待结算机制。
- 新记忆设置界面接候选、确认、纠正、删除及来源/覆盖状态；S 摘要必须接入实际运行，不能只保留测试 API。

## 3. 模型与预算：需要确认的产品选择

推荐保留 OpenRouter 和现有厂商适配，不为启用记忆强制切换到 GPT-5.2。

有经过核验的精确计数能力时采用精确预算；其他服务使用明确标注、带版本和安全余量的估算预算，并结合服务端实际 usage 校验。估算不表示生成前必然符合模型窗口，不将简单字节计数冒充精确证明；超限、能力不支持或配置缺失给明确错误，不回退旧记忆链。

公共 OpenRouter 元数据列出了 openai/gpt-6-luna 的工具和推理能力，但未证明用户账户调用成功，也未找到通用的生成前精确计数接口。本次不复用原本仅用于隔离验收的固定一美元诊断账本作为生产费用策略，不新增付费测试授权。

预算针对实际序列化请求；发送必须复用同一已准备请求或验证相同序列化内容，不能预算后重新拼接请求导致内容改变。使用既有模型档案中的输出、超时及上下文限制，不擅自调大。

## 4. 旧链退出与资料保留

停止个人 PMRS/L0/L1/L2 自动维护、旧 user_memory/chat_history 的读写工具、索引协调及旧 Vault 回流。所有普通入口都不得悄悄调用 recall_history 补齐新 H。

保留世界书/人设、imported_docs 文档检索、Work 知识工作区、表情/心情副作用、ASR、提示音和普通音频。拆分原来的混合函数，不能删除整个 RAG 目录或整段完成回调。

旧原始会话和文件保留，不自动迁移、修剪或补造 snapshot。无 snapshot、数量/大小上限或缺少证据时显示覆盖不足，不能显示为空且暗示没有历史。历史迁移另行授权。

原生 helper、密钥保护、本地模型等依赖须有构建/打包检查和明确状态。相关能力不可用时不损坏原文件、不伪造可用状态；不能仅靠启动成功判定记忆功能完成。

附件消息、取消、编辑、删除分别至少有一个负向用例：非法/越权附件显式拒绝；取消后的迟到发送/提交显式拒绝；编辑后旧版本来源失效并拒绝旧证据；删除后旧来源/能力拒绝读取。断言稳定拒绝码与零未授权副作用，不能仅断言空结果或没有崩溃。

跳过项逐项记录名称、原因、源码条件及环境，Windows 专项按 DPAPI、native helper、8.3 短路径、符号链接四类单列。未执行或跳过均不算通过；不能改变系统设置或把 skip 改成成功来获取绿色。
