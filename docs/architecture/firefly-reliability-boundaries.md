# Firefly 可靠性维护边界

本文承接退出当前工作树的旧问题调查、重构施工及存储草案中的技术约束，不重新开展架构审计，也不把历史修复记录当成本轮验证。原始堆栈、当时的提交和实测数字保留在 Git 历史；迁移批次实测记录仍独立保留。

## 运行与持久化

- 会话占用与运行终态是不同状态；取消、并行工具抛错或 halt 后，已执行的结果不能丢失，不能留下悬空运行。恢复上下文必须保持工具调用和结果配对，不能制造孤儿结果。
- 门面与叶子模块保持原职责。终态映射不承担持久化副作用；运行存储与审查收尾继续由原编排层调用，不新建事件总线或第二套存储。
- checkpoint 的写入次数和深拷贝开销是性能回归关注点，不用固定延时解锁或牺牲一致性掩盖延迟。
- CI 实际覆盖范围、依赖检查和打包验证分别记录。绿色小测试组不等于整个测试全集通过。
- Memory 失败恢复不能覆盖唯一原文件；渠道发送结果、历史提交与用户看到的内容必须区分，不能把发送失败记作成功。

## 图片与输出预算

`src/main/orchestrator/context-manager.ts` 与上下文用量展示使用一致的图像估算口径，不能把 base64 字符长度直接当作图片 token 数。图片路由依据模型能力，不仅依据协议名称。压缩后的展示应反映对应会话而不是下一次请求才刷新。

`src/main/orchestrator/harness/harness-llm.ts` 的输出上限与上下文预留预算是不同概念。具体厂商参数由当前适配器和能力定义决定；旧调查中的服务示例、型号表和数字不能作为新的默认配置依据。

## 文件、Shell 与权限

捕获层截断、模型窗口截断、文件 EOF 和完整读取是不同结论。保留尾部错误与完整性信息；取消和超时必须传递至实际执行链。工具 schema、模式过滤和执行可用性应一致；缺参数应报告失败而不是编造参数继续覆盖文件。覆盖写入与审查快照遵守现有授权和证据链，不通过改名扩权。

## 渲染与未决观察

性能以运行时测量为依据，不能由 ticker 上限、memo 数量或旧调研推断通过。长列表、全量消息重建、会话缓存释放、侧栏与 Tabs 的刷新仍是相关修改时的回归关注点。Markdown 保留净化和链接边界，不以删除安全插件作为性能优化。

过去的主动聊天未触发反馈不等于已复现；再次调查需要触发时间、开关和调度状态的无私人内容证据。历史恢复 400、工作区提示、工具卡折行与终端输出等旧待办，本轮不新增实现或宣称全部已解决。

## 记忆与渠道绑定

记忆算法与 L2 使用 `src/main/memory/l2-dmae-manager.ts` 及现有 Memory 所有者，不按旧草案重新迁移用户记忆或调整衰减参数。渠道会话绑定使用 `src/main/channels/conversation-binding-store.ts` 和 `conversation-binding-api.ts`；绑定不等于全设备同步，不改变渠道凭据或桌面权限。身份、消息关联和保存失败保护不能因品牌更名丢失。

外部研究与依赖的真实身份保留于许可和来源声明；旧文档中未核实的依赖风险、渲染缺陷或功能建议，须在对应功能被明确安排时取证，不能因为本文收纳而标记关闭。
