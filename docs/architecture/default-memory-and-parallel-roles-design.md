# 普通启动 S/M/H 与多角色并行协作设计

日期：2026-10-06；源码基线：771f302。状态：已按用户 2026-10-06 03:06 UTC 的评审意见修订，尚未实现。本次只修改自己的云端源码副本，不操作用户电脑、不调用付费模型或真实渠道账户。

## 1. 用户目标

普通启动全面替换旧个人记忆链；同一任务可组合调用多个专业角色并协作。保留现有模型档案（包括 OpenRouter 的 openai/gpt-6-luna）、历史数据、权限和角色资源。不能通过仅开启诊断开关、仅修改提示词或扩大权限宣称完成。

## 2. 默认记忆运行

- 普通启动装配统一 Main 记忆服务，不再依赖 firefly-memory-controlled，不再仅接受默认档案的无工具 Chat。
- S 负责当前会话上下文及摘要；M 负责有来源的长期事实、候选与确认/纠正/遗忘；H 负责可核验历史读取。多轮工具调用和结果必须作为完整单元参与预算、持久化和恢复。
- 桌面 Chat/Work/Code、渠道、定时任务、子角色及主动消息分别使用可信来源适配。渠道按账号、发送者与群聊隔离；不把外部发送者自动当作本地主人。委派指令、计划与模型输出不得写成用户陈述事实。
- 临时会话不读写持久 M/H。非交互任务只在已有授权范围读取。附件保留原有文件权限和出处，不能因启用新记忆而拒绝所有带附件消息或自动永久记住附件内容。
- 使用真实模型档案身份与配置版本，变更后撤销旧请求权限；保留取消、编辑、删除、关闭时的失效与等待结算机制。
- 新记忆设置界面接候选、确认、纠正、删除及来源/覆盖状态；S 摘要必须接入实际运行，不能只保留测试 API。

## 3. 模型与预算：需要确认的产品选择

推荐保留 OpenRouter 和现有厂商适配，不为启用记忆强制切换到 GPT-5.2。

有经过核验的精确计数能力时采用精确预算；其他服务使用明确标注、带版本和安全余量的估算预算，并结合服务端实际 usage 校验。估算不表示生成前必然符合模型窗口，不将简单字节计数冒充精确证明；超限、能力不支持或配置缺失给明确错误，不回退旧记忆链。

公共 OpenRouter 元数据列出了 openai/gpt-6-luna 的工具和推理能力，但未证明用户账户调用成功，也未找到通用的生成前精确计数接口。本次不复用原本仅用于隔离验收的固定一美元诊断账本作为生产费用策略，不新增付费测试授权。

预算针对实际序列化请求；发送必须复用同一已准备请求或验证相同序列化内容，不能预算后重新拼接请求导致内容改变。使用既有模型档案中的输出、超时及上下文限制，不擅自调大。

## 4. 旧链退出与资料保留

停止个人 PMRS/L0/L1/L2 自动维护、旧 user_memory/chat_history 的读写工具、索引协调及旧 Vault 回流。所有普通入口都不得悄悄调用 recall_history 补齐新 H。

保留世界书/人设、imported_docs 文档检索、Work 知识工作区、表情/心情副作用、ASR、提示音和普通音频。拆分原来的混合函数，不能删除整个 RAG 目录或整段完成回调。

旧原始会话和文件保留，不自动迁移、修剪或补造 snapshot。无 snapshot、数量/大小上限或缺少证据时显示覆盖不足，不能显示为空且暗示没有历史。历史迁移另行授权。

原生 helper、密钥保护、本地模型等依赖须有构建/打包检查和明确状态。相关能力不可用时不损坏原文件、不伪造可用状态；不能仅靠启动成功判定记忆功能完成。

## 5. 多角色完整协作

沿用 12 个角色、45 项技能、单角色 delegate_agent 和现有结果/UI协议。允许一轮发出多个不同角色委派，角色独立会话，结果保留身份和失败状态。初始并行上限 min(3, 现有 maxParallelToolCalls)，不默认同时调用全部 12 个；同一角色仍单飞。

主模型与子角色思考、明确安全的读取可并行。父运行共享执行协调器，对写文件、Shell、未知插件和网页动作等串行协调，沿用审批及取消。委派本身不占用叶子工具锁，避免父等子、子等锁的死锁。

并行组对可识别的文件写入保留按规范路径的角色所有权，首次实际获批写入时认领；同组另一角色写入同一路径返回 AGENT_WRITE_CONFLICT 并终止该子任务，交主代理调整分工或另开顺序委派，不准转 Shell 绕写。多文件补丁先整体核对所有目标（含移动源和目标），避免半组认领。逐工具互斥不等于文件事务隔离；范围不明的命令保持独占，不将其描述为完全解决任意外部副作用冲突。排队取消与实际仍运行的工具分开结算，不能提前释放尚未停止操作的锁。

本轮保持 Chat 不自动委派、Work/Code 原有角色可用性；父任务的工作区、模型、工具和审批范围不会因多角色而扩大。

## 6. 两个独立交付与新增验收口径

交付 ①：普通启动 S/M/H 与旧个人记忆链退出，按独立提交、运行证据及验收报告交付。交付 ②：多角色并行与写入协调，单独提交和验收；不得以其中一项完成代表两项都完成。先实施 ①，再实施 ②。

并行证据使用同一时钟域的单调递增序号、单调时间戳、角色 ID、父/子运行 ID、阶段与终态，记录实际进入/离开模型执行的事件。以 `A.start < B.start < min(A.end, B.end)` 或等价区间重叠证明至少两个角色同时运行，不靠 Promise 创建顺序或状态推断。

冲突导致子任务终止时，已完成写入原位保留、不自动回滚。终态结果及界面须逐项列出完成写入路径、可用前后哈希/版本及工具事件，分别标记 applied、partially_applied、unknown、not_applied；不得把整次任务写成零修改或仅显示失败。其他角色的结果仍保留。

范围不明的 Shell 占用同一工作区独占执行许可，阻塞其他角色的工具读取和写入；模型思考可以继续。读取正在写的文件必须等实际写入 Promise 结算后取得读取许可，记录实际读取的版本/哈希；先前已读取的版本不自动变成新版本。取消等待不表示底层操作已停，不得提前放开冲突操作。

附件消息、取消、编辑、删除分别至少有一个负向用例：非法/越权附件显式拒绝；取消后的迟到发送/提交显式拒绝；编辑后旧版本来源失效并拒绝旧证据；删除后旧来源/能力拒绝读取。断言稳定拒绝码与零未授权副作用，不能仅断言空结果或没有崩溃。

跳过项逐项记录名称、原因、源码条件及环境，Windows 专项按 DPAPI、native helper、8.3 短路径、符号链接四类单列。未执行或跳过均不算通过；不能改变系统设置或把 skip 改成成功来获取绿色。

## 7. 共同验收

- 无诊断开关普通启动；多个保存的模型档案；Chat/Work/Code 工具多轮、附件、重试、摘要、取消、编辑与删除。
- 桌面/渠道/定时/子角色/主动入口无旧个人记忆调用；模型生成内容不会冒充用户事实；世界观、文档知识及音频功能保留。
- M 候选/确认/纠正/遗忘与新设置界面实际接线；H 覆盖不足显性；旧数据零补写及无旧链回退。
- 至少两个不同角色可同时在运行；共享安全读可并行，写操作不重叠，冲突可见；部分失败不隐去其他结果，父取消能停止排队及传递取消。
- 完整自动测试、类型检查、构建与存储边界检查；归档每项跳过原因。原生 Windows/DPAPI/helper 打包与真实模型验收单列，不用 Linux 合成测试替代。
- 交付提交、源码增量、运行证据及剩余外部条件，区分代码实现、测试、整合和发布。
